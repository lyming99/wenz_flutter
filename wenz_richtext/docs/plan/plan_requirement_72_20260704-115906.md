## 背景与影响范围

本需求中的“图片”按项目现有模型解释为顶层块级图片 `ImageBlockNode`，不包含行内图片 `InlineEmbed(embedType: 'image')`。当前代码已经具备部分基础：

- `ImageBlockNode` 继承 `BlockNode`，可通过 `BlockAttributes.alignment` 持久化块级对齐属性，rich JSON 的 `attrs.alignment` 已能随 `baseJson()` / `attrsFromJson()` 往返。
- `SetAlignmentCommand` 当前会更新非表格选择范围内块的 `BlockAttributes.alignment`，现有 `test/core/style_commands_test.dart` 已覆盖图片这类非文本块可写入 alignment。
- `ToolbarController` 的 `_collectBlockAlignment` 会读取非表格块 alignment，理论上图片对象选区已可被工具栏识别为可设置对齐。
- 主要缺口在默认图片渲染：`_ImageBlockContent` 当前固定 `AlignmentDirectional.center`，因此即使图片块已写入 `attrs.alignment`，视觉仍然居中；`_MediaBlockChrome` 的对象工具栏 anchor 也固定按居中 frame 处理。
- HTML codec 当前导出图片为 `<img>` 或 `<figure>`，未显式保存图片块对齐；Markdown 没有通用图片块对齐语义，应保持降级，不强行引入非标准扩展。

## 实施策略

复用已有块级属性和命令链路，不新增 `ImageBlockNode` 字段、不提升 schema version。渲染层根据 `ImageBlockNode.attributes.alignment` 决定图片 frame、caption、选中描边和对象工具栏的水平位置：显式 `left` 对齐到 start，`center` 居中，`right` 对齐到 end；`null` 保持现有默认居中，避免旧文档视觉回归。`justify` 对图片无自然拉伸语义，计划作为不拉伸的安全回退处理，并在文档中明确。HTML 导入导出补齐对齐保真，rich JSON 通过既有 attrs 机制保真。
