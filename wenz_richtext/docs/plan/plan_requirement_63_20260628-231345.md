# 需求 #63 开发计划：图片/视频块显示设计稿先行 + 按设计稿优化渲染

- 需求编号：#63
- 创建日期：2026-06-28
- 状态：待评审

## 需求概述

当前编辑器虽已支持 `BlockType.image` / `BlockType.video` 块的插入与占位渲染（`_defaultImageBlockRenderer` / `_defaultVideoBlockRenderer`），但**图片/视频的「显示」缺乏专门设计**：占位简陋、关键字段未渲染、状态覆盖不全。本需求采用「先设计、后落地」的方式，分两步推进：

1. **先设计**：在 `ui/` 文件夹新增一份**图片/视频块显示**的 HTML 设计稿（纯 HTML/CSS、无外部依赖、浏览器可直接打开），覆盖图片与视频块的全部显示状态与交互细节，风格对齐既有 `ui/slash_popup_electron_design.html`（Electron 桌面端克制风格，复用 colorScheme token，全中文文案）。
2. **再优化**：依据该设计稿，优化 `lib/src/widgets/wenz_rich_text_editor.dart` 中图片/视频块的渲染（补齐 caption 渲染、收敛 chrome token、补全占位/加载/失败/选中/只读状态），并补一份设计规范 md 作为设计→代码的 token 契约。

> 范围限定为**图片/视频块的显示与交互态**（figure chrome、caption、占位、状态、选中描边、只读裁剪）；不新增视频播放器/网络图片插件依赖（维持 `MediaResolver` 注入式架构），不改图片/视频块的 schema、插入/删除/序列化逻辑与既有手势/选区/预览行为。

## 现状分析（勘察结论）

- **块模型已就绪**：`lib/src/core/model/block_node.dart`
  - `ImageBlockNode`（约 212 行）：`assetId` / `file` / `showWidth` / `showHeight` / **`caption`** / **`altText`**。
  - `VideoBlockNode`（约 395 行）：`assetId` / `file` / `coverUrl` / `aspectRatio`（**无 caption 字段**，故 caption 渲染仅限图片块）。
- **caption / altText 当前未被渲染**（核心差距）：`_ImageBlockContent`（`wenz_rich_text_editor.dart:11333`）只构建 figure 外框（`surface` 底 + `_kMediaCornerRadius` 圆角 + `_kSurfaceBoxShadow` 阴影 + `ClipRRect`），**完全没有渲染 `block.caption` / `block.altText`**；`_VideoBlockContent`（10244 行）同样无 caption。而 `ui/richtext_design.html:657-671` 的图片 section 已示范 `<figcaption>`，模型也早已支持——属于「设计有、模型有、渲染缺」。
- **图片占位过简**：`_ImageBlockPlaceholder`（9754 行）是固定 `112×72` 的小图标盒（`image_outlined` 图标 + `surfaceContainerHighest` 底），**不撑满内容宽度、不与 figure chrome 对齐、无空/加载/失败的语义状态区分**。
- **视频占位相对完整但无失败态**：`_VideoBlockPlaceholder`（9779 行）已含封面背景 `_VideoCoverBackdrop`、渐变、播放按钮（`_videoPlayButtonSizeFor` / `_kVideoPlayIconSize`）、封面 chip，并经 `LayoutBuilder` 做了帧约束与圆角，但**无 loading/buffering/failed 等状态**，且与图片占位 token 不统一。
- **既有设计稿对图片/视频覆盖过浅**：`ui/richtext_design.html` 是覆盖 15 类块的总览稿，其图片（section 9）/视频（section 10）仅各 1 个极简示例（figure + placehold.co 占位图 / 一个 ▶ 播放钮），**没有 chrome、状态、选中、只读、caption 编辑、尺寸等细节**，不足以指导落地。
- **无图片/视频显示的专门设计稿**：对照 `slash_popup_electron_design.html`（斜杆 popup 专门稿）+ `menu_toolbar_minimal_design.html`（菜单/工具栏专门稿）的既有范式，图片/视频块**缺少同等的专门设计稿**，这正是本需求「先用 html 设计」要补齐的产物。
- **可复用的 chrome token**：`_kMediaCornerRadius`、`_kMediaBlockMarginVertical`、`_kSurfaceBoxShadow`、`_kVideoFrameFallbackWidth`、`_kVideoPlayIconSize` 等常量已是图片/视频块共享入口；设计稿与规范应围绕这组 token 收敛，而非新增散落硬编码。
- **选中描边已独立于通用 overlay**：`_MediaSelectionStroke`（11403 行）在媒体框自身矩形上绘制 `primary` 2px 描边（非通用 `_BlockObjectSelectionSurface`），媒体块禁用通用 overlay。优化时保留该机制，仅按规范对齐圆角/线宽。
- **预览能力已存在**：`_showImagePreview` / `_showVideoPreview`（5837/5897 行调用）提供双击/激活预览；优化不触碰其行为。
- **既有测试**：`test/widgets/media_resolver_test.dart`（resolver 注入覆盖）、`test/widgets/wenz_rich_text_editor_test.dart`（结构性/交互用例）、`test/widgets/editor_golden_test.dart`（含 `editor_advanced_blocks.png` / `editor_blocks.png` / `editor_theme_light.png` / `editor_theme_dark.png` 等，**图片/视频 chrome 变更将影响这些 golden**）。
- **依赖约束**：`pubspec.yaml` 仅有 `flutter` / `flutter_math_fork` / `highlight` / `html`，无 `image` / `video_player` 等——本计划维持该约束，真实图片/视频解码仍由宿主经 `MediaResolver`（`media_resolver.dart`）注入。

## 方案与关键决策

1. **先产出专门 HTML 设计稿**：新建 `ui/media_block_display_design.html`，作为图片/视频块显示的**唯一视觉来源**，风格与 `slash_popup_electron_design.html` 同源（Electron 桌面克制：两层弱阴影、清晰层级、紧凑节奏；复用 colorScheme token；全中文文案；纯 HTML/CSS 无依赖、浏览器可直接打开）。同时在 `ui/richtext_design.html` 的图片/视频 section 增加一句指向新稿的说明，保持两稿口径一致（不重写总览稿）。
2. **设计稿覆盖「状态全集」而非单例**：图片块覆盖 figure chrome（圆角/阴影/最大宽度/caption/altText）、显示尺寸（showWidth/showHeight）、状态（空占位 / 加载上传中 / 已加载 / 加载失败、默认 / 悬停 / 选中描边 / 只读裁剪）；视频块覆盖封面预览 + 播放覆盖层（默认/悬停/按下）、播放/缓冲/失败/占位态、宽高比处理、选中描边；并提供明色 + 暗色 token、设计 Token 参数面板与色板（映射到 `_kMediaCornerRadius` 等常量）。
3. **补一份设计规范 md 作为 token 契约**：新建 `docs/design/media_block_display_spec.md`，结构对齐 `docs/design/menu_toolbar_minimal_spec.md`（HTML 设计稿来源 → 覆盖范围 → 状态约束 → 视觉 Token → 现有样式入口）。把设计稿里的 chrome/spacing/typography/selection/motion token **显式映射到 Flutter 常量名**，并写明 caption 渲染契约与各占位态契约，使「按设计稿优化」可被逐项验收。
4. **caption 渲染补齐（仅图片块）**：`_ImageBlockContent` 在 figure 外框下方渲染 `block.caption`（figcaption：`onSurfaceVariant` 小号文案、居中、受最大宽度约束）；`caption` 为空时不占额外空间；`altText` 接入 `Semantics` 用于无障碍朗读。视频块模型无 caption 字段，本期不引入。
5. **图片占位重做、状态区分**：`_ImageBlockPlaceholder` 重做为「撑满内容宽度的 figure chrome 空态」（图标 + 简体中文提示），并新增**加载中（上传中）**与**加载失败**两个占位态——后者与「无 resolver / resolver 抛错」的回退路径（`media_resolver.dart` catch-and-fallback 契约）对接，使失败态可与空态区分。
6. **视频占位补失败态、token 对齐**：`_VideoBlockContent` / `_VideoBlockPlaceholder` 按 spec 收敛圆角/阴影/播放按钮 token，并补一个**加载失败**回退态（区别于封面占位），保留宽高比归一（`_safeVideoAspectRatio` / `_videoFrameHeight`）与溢出夹紧、双击预览行为不变。
7. **不动行为、只动显示**：不改 schema、序列化、插入/删除命令；不改 `_MediaSelectionStroke` 的命中/几何注册与双击预览；不改 `MediaResolver` 接口；不新增平台依赖到库 `pubspec.yaml`。仅更新显示层（chrome token、caption、占位态）。
8. **golden 受影响按需重生成**：图片/视频 chrome 与 caption 变更会影响 `editor_advanced_blocks.png` 等静态 golden；验收时仅在确认影响后执行 `flutter test --update-goldens` 并人工核对差异仅限预期区域，否则不动 golden。
