# 需求 #43 开发计划：点击空白位置按视觉行计算光标

- 需求编号：#43
- 生成时间：2026-07-03 15:58:51
- 需求内容：点击空白位置，计算光标位置存在问题，应该先计算点击位置所在行，再根据 x 位置计算所在行文字位置。

## 背景与影响范围

当前编辑器的点击定位链路是 `SelectionGestureOverlay._onPointerDown` 记录 pointer-down 坐标，调用 `BlockGeometryRegistry.positionFromGlobalOffset` 命中文本 surface，再由 `_TextSelectionSurface._offsetForLocalPosition` 把 text-local 坐标传给 `TextLayoutService.offsetAt`。`TextLayoutService.offsetAt` 目前直接调用 `TextPainter.getPositionForOffset(localPosition)`，没有先锁定视觉行。

该实现对正文字符点击、空段落点击、跨块拖拽已经有覆盖，但对“有文字的视觉行右侧空白区域”存在风险：在自动换行或显式换行场景中，点击点的 x 落在当前行文字之后时，应先按 y 判断所在视觉行，再按该行内 x 推导 offset；否则可能跳到相邻视觉行、块尾或其他错误位置。本需求不需要改文档 schema、selection 模型、命令层或文本输入层，核心影响范围集中在文本布局命中服务及其调用链回归测试。

## 实施策略

采用“共享布局服务修正 + 交互回归固定”的方案。`TextLayoutService.offsetAt` 作为文本 surface 坐标到 render offset 的唯一共享入口，应使用 `TextPainter.computeLineMetrics()` 先解析 localPosition.dy 所在的视觉行；当 y 位于行外时选择最近视觉行，当 x 位于该行文字左侧或右侧空白时交给同一行中心 y 的 `getPositionForOffset` 解析，使结果自然落到该行行首或行尾。调用方 `_TextSelectionSurface`、`BlockGeometryRegistry` 继续负责 global/local 坐标转换、空文本 offset 0、表格/代码块可见区域 clamp，不重复实现行命中算法。

测试按三层补齐：`TextLayoutService` 单元级固定行优先 offset 规则；编辑器 widget 级覆盖真实点击右侧空白后的 selection；示例 integration 级补充指针精度场景，防止鼠标点击路径回归。
