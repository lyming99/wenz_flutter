# 反馈 #53 开发计划：大纲折叠按钮不占用正文位置

## 需求描述

> 大纲折叠按钮，不要影响正文对齐，不要占用正文位置

当前问题：heading 折叠按钮在编辑器正文区域左侧 rail 内渲染时，会导致该 heading 行内容左侧 padding 比非 heading 行多出约 32dp（当前 `railWidth = 68dp`，而仅有拖拽 handle 时为 `hitSize + gapToContent = 36dp`），造成 heading 正文与其他非 heading 正文水平不对齐。

## 技术分析

### 当前布局结构

```
_BlockDragHandleOverlay (Stack, clipBehavior: Clip.none)
├── content (Padding start: activeChromeWidth)
├── drag handle (Positioned start: 0, 28×28)
└── collapse button (Positioned start: 36, 24×24)
```

当前 activeChromeWidth 计算逻辑（`_BlockDragHandleOverlayState.build()` 行 6652-6657）：

- 有折叠按钮 → `BlockDragHandleSpec.railWidth = 68dp`（28 handle + 8 chromeGap + 24 button + 8 gapToContent）
- 仅有拖拽 handle → `hitSize.width + gapToContent = 36dp`
- 两者都无 → `0dp`

这导致 heading 正文被额外推右 32dp，与非 heading 行正文不对齐。

### 关键常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `BlockDragHandleSpec.railWidth` | 68.0 | 为折叠按钮预留的总宽度 |
| `BlockDragHandleSpec.hitSize.width` | 28.0 | 拖拽 handle 宽度 |
| `BlockDragHandleSpec.chromeGap` | 8.0 | chrome 控件之间的间距 |
| `BlockDragHandleSpec.gapToContent` | 8.0 | chrome 控件到正文的最小间距 |
| `_kHeadingCollapseSlotWidth` | 24.0 | 折叠按钮槽位宽度 |
| `_kHeadingCollapseButtonSize` | 24.0 | 折叠按钮尺寸 |

### 修复方案

采用 **OverflowBox** 方案，让折叠按钮浮动在 rail 的 gutter 区域内而不占用正文 padding：

1. **content padding 统一化**：heading 行的 content padding 与普通行一致（有 drag handle 时 36dp，无 drag handle 时 0 或最小缩进）
2. **折叠按钮浮动渲染**：使用 `OverflowBox(maxWidth: 0, alignment: centerEnd)` 包裹折叠按钮，使其在 layout 中占 0 宽度但视觉上向左延伸到 gutter 区域
3. **railWidth 语义更新**：`BlockDragHandleSpec.railWidth` 不再包含折叠按钮宽度，仅保留 drag handle + gap；可新增一个 `collapseChromeOverflow` 或类似常量标记溢出区域

修改涉及的代码范围：
- `lib/src/widgets/wenz_rich_text_editor.dart` — `_BlockDragHandleOverlayState.build()`
- `lib/src/widgets/block_renderer_registry.dart` — `BlockDragHandleSpec.railWidth` 及其注释
- `test/widgets/editor_golden_test.dart` — golden 测试截图更新
- `test/widgets/wenz_rich_text_editor_test.dart` — heading collapse 对齐测试
