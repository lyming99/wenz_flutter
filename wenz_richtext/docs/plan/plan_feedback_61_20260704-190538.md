## 背景与现状

项目是 Flutter 富文本编辑器 package。结合当前源码，粘贴链路主要是 `WenzRichTextEditor._handlePaste` 读取平台剪贴板后调用 `WenzRichTextController.pasteText/pasteHtml/pasteMarkdown`，控制器再通过 `ClipboardService.parse` 区分 Wenz rich JSON、HTML/Markdown block paste、rich inline paste 和 plain text paste。

反馈中的“在代码块里面粘贴内容时，收到大量编辑事件，导致卡顿”对应当前控制器实现里的 plain text paste 分支：`WenzRichTextController._pastePlain` 会先 `text.split('\n')`，首行调用 `insertText`，后续每一行先调用 `enter` 再调用 `insertText`。而 `WenzRichTextController.execute` 每执行一个非 no-op 命令都会同步触发 `onChanged`、`onSelectionChanged`、`onCommandExecuted` 和 listener 通知。对于 `CodeBlockNode`，`EnterCommand` 只是向同一个代码字符串插入换行，因此一段 500 行代码会产生近千次命令/回调/重绘，而实际期望只是一次“把原始代码文本插入代码块”的编辑。

关键约束是不要绕过命令层直接改 document。现有 `InsertTextCommand` 已经支持在 `CodeBlockNode` 的 `PositionPath.blockCode` 中一次插入包含 `\n` 的字符串，并能保留 undo/redo、permission gate、selection、schema normalize、`lastChangedBlockIds` 和回调顺序。因此最小方案是在 plain text paste 进入逐行拆分前识别“当前粘贴目标是代码块”，直接以一次 `insertText(text, applyMarkdownShortcuts: false, applyAutoLinkUrls: false)` 完成整个原始文本插入，并避免额外的裸 `notifyListeners()`。

## 目标

- 在代码块内粘贴多行纯文本时，不再按行拆成大量 `enter/insertText` 命令。
- 一次代码块粘贴只产生一次文档变更事件和一次命令执行事件，listener 通知也不随行数增长。
- 粘贴内容必须原样保留换行、空行、缩进、尾随换行和普通代码字符，不触发 Markdown shortcut 或 URL 自动链接。
- 保持代码块语言、块属性、selection 替换、撤销/重做、权限控制、`lastChangedBlockIds` 等现有命令层语义。
- 非代码块纯文本多行粘贴、rich JSON 粘贴、HTML/Markdown 粘贴、外部图片粘贴、表格单元格粘贴优先级和行为不因本次优化回归。
