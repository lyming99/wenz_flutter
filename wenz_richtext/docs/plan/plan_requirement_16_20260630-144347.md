## 需求概述

为 `wenz_richtext` 编辑器补齐一组面向富文本结构与插入动作的默认快捷键，并确保这些快捷键可通过现有 `EditorShortcutConfiguration` / `WenzEditorConfiguration.shortcutConfiguration` 进行覆盖、禁用或透传。

默认快捷键解释如下：

| 快捷键 | 默认动作 |
| --- | --- |
| `Ctrl+1` ~ `Ctrl+6` | 分别切换 H1~H6；若当前选区已全为同级标题，则切回正文段落 |
| `Ctrl+8` | 切换引用 |
| `Ctrl+9` | 输入公式 |
| `Ctrl+Alt+K` | 切换代码块 |
| `Ctrl+T` | 切换 Todo |
| `Ctrl+I` | 无序列表 → 有序列表 → 清除列表；非列表先变无序列表 |
| `Ctrl+Shift+T` | 插入表格 |
| `Ctrl+Shift+L` | 插入链接，弹窗包含标题与链接 |

> 备注：需求中的 `ctrl+shit+t` / `ctrl+shit+l` 按常见键位拼写解释为 `Ctrl+Shift+T` / `Ctrl+Shift+L`。

## 现状分析

- 快捷键解析集中在 `lib/src/input/shortcut_manager.dart`：已有 `EditorShortcutIntent`、`EditorShortcutConfiguration`、`EditorShortcutBinding`、`EditorShortcutKey`、`EditorShortcutManager.resolve()`；自定义配置优先于内置 keymap，支持 `handled` / `ignored` / `passThrough` 与 `disabledIntents`。
- 编辑器执行入口集中在 `lib/src/widgets/wenz_rich_text_editor.dart`：`_handleKeyEvent()` 调用 `_shortcutManager.resolve()`，再由 `_performShortcut()` 将 intent 转为 controller 操作；已处理选择、撤销重做、剪贴板、查找替换、光标移动、删除、回车与字符输入。
- 配置已透传：`WenzRichTextEditor.shortcutConfiguration` 会在 `didUpdateWidget()` 重建 resolver；`WenzEditorBootstrap.buildEditor()` 会先合并插件快捷键，再合并宿主 `WenzEditorConfiguration.shortcutConfiguration`，宿主配置后置且胜出。
- 富文本命令基础已存在：`WenzRichTextController.setBlockType()` 可设置段落/标题/列表，`toggleTodo()`、`toggleQuote()`、`insertFormula()`、`setLink()`、`insertTable()` 已存在；表格、内联公式、链接的底层命令也已在 `core/commands` 中实现。
- 缺口集中在三处：新增富文本快捷键 intent 与默认映射、将新增 intent 接入 `_performShortcut()`、为“代码块切换”和“标题+链接插入”补齐复用现有命令/弹窗的执行辅助。
- 测试基础已存在：`test/input/shortcut_manager_test.dart` 覆盖 keymap 解析；`test/widgets/wenz_rich_text_editor_test.dart` 与 `test/widgets/link_edit_dialog_test.dart` 可覆盖 widget 级快捷键行为和链接弹窗。

## 方案与边界

- 复用现有配置模型，不引入新的快捷键配置入口；新增默认快捷键也必须能通过 `EditorShortcutConfiguration.bindings` 覆盖为其他组合、`ignored` 禁用、`passThrough` 交给宿主。
- 默认组合按需求使用精确 `control` 修饰键；不默认扩展为 macOS `meta`，但宿主可自行用 `primary` 或 `meta` 追加别名。
- 新增动作仍通过 controller / command 进入历史、权限与中间件链路；widget 层只做弹窗、焦点、当前 selection 与生成 id 等 UI 编排。
- 读模式下所有新增写入型快捷键必须被忽略，不修改文档，不弹出插入类 UI。
- 链接弹窗升级为“标题 + 链接”时需保持现有 hover 编辑链接能力兼容；已有只编辑 URL 的入口不能回归。
- 本计划只描述开发任务与验收标准，不修改业务代码。
