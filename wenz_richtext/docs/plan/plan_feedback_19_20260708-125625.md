# Fix Shift plus mouse selection in the rich text editor

## 需求概要

Feedback #19 reports that Shift plus mouse selection is broken. In the current implementation, `SelectionGestureOverlay` owns document-level pointer selection, but it treats a primary click as caret placement and a drag as a new selection from the pointer-down position. Keyboard Shift expansion is already handled through shortcut commands, yet the pointer path has no access to the current controller selection and does not preserve an existing anchor when Shift is held. The fix should add Shift-aware click and drag semantics to the gesture overlay, thread the current selection from `WenzRichTextEditor`, and cover text, cross-block, table/code/object-adjacent behavior without regressing normal click, drag, multi-click, link modifier-click, context menu, scrollbar gutter, or read-only selection.

  - 验收要点：When Shift is held during a mouse primary click and the editor already has a selection, the overlay emits a range from the existing selection anchor to the clicked document position instead of collapsing the caret.
  - 验收要点：When the existing selection is collapsed, Shift-click uses the collapsed caret as the base and the clicked position as the extent.
  - 验收要点：When the existing selection is expanded, Shift-click preserves the existing base and only moves the extent, including reverse extension when the clicked point is before the base.
  - 验收要点：Shift plus mouse drag starts from the existing selection anchor and continuously updates the extent through `BlockGeometryRegistry`, including cross-block drag and drag into gaps that clamp to nearest text positions.
  - 验收要点：If there is no current selection or the pointer cannot resolve a document position, behavior falls back to the current normal click and drag semantics.
  - 验收要点：Non-Shift single click, normal drag, double-click word selection, triple-click block selection, touch long-press selection, context-menu pointer handling, scrollbar gutter exclusion, and selection exclusion zones remain unchanged.
  - 验收要点：Ctrl/Cmd plus link click continues to open links with the existing precedence and does not accidentally create a Shift selection when the link-open path handles the pointer.
