# 开发计划：反馈 #26 代码块多语言语法高亮（接入 highlight 库）

## 反馈原文

> 代码块高亮要支持多种语言，请使用代码高亮相关依赖库实现

## 背景与现状

- 代码块高亮当前由手写分词器 `lib/src/widgets/code_syntax_highlighter.dart` 的 `_tokensForLanguage` 实现，**仅支持 dart / javascript / typescript / json / markdown** 5 种语言；其余语言返回 `null`，退化为等宽纯文本，无任何 token 着色。
- 语言选择器 `_kDefaultCodeLanguages`（位于 `lib/src/widgets/wenz_rich_text_editor.dart:12110`）对外列出了 16 种语言（dart/js/ts/python/java/kotlin/swift/go/rust/sql/json/yaml/html/css/markdown/bash），但其中 **11 种实际未被高亮**，与“支持多种语言”的预期不符。
- `CodeSyntaxHighlighter.highlight(code)` 返回 `TextSpan`，由 `wenz_rich_text_editor.dart` 的 `_codeSpan()`（`:12084`）调用，并叠加了 **IME 合成区域下划线**（`compositionStart/compositionEnd` → `_appendSegment`，`:106`）。该合成下划线能力在改造后必须保留，否则中文输入法的候选拼写下划线会丢失。
- 已有相关测试：`test/widgets/wenz_rich_text_editor_test.dart` 中的 `code block syntax highlights supported languages and leaves unsupported plain`，以及 `test/widgets/editor_golden_test.dart` 的代码块快照。

## 选型说明（重要）

- 选用 **`highlight` 核心库（`highlight: ^0.7.0`）**：highlight.js 的 Dart 移植，约 192 种语言、MIT 协议、Dart 3 兼容、仅依赖 `collection`，与本项目 SDK `>=3.3.4 <4.0.0` 不冲突。其 `highlight.parse(code, language: x)` 返回 `Result`，`Result.node` 为带 `className`（scope）的 `Node` 树，可自行遍历为 `TextSpan`。
- **不使用 `flutter_highlight`**：它对外暴露的是 `HighlightView` Widget，而代码块在编辑器内是作为 `TextSpan` 嵌入统一的 `Text.rich` 渲染管线（含行号栏、选区命中、IME 合成下划线、复制/编辑）。替换成独立 Widget 会破坏上述管线，代价过大。
- 因此方案为：**保留并复用 `CodeSyntaxHighlighter` / `CodeSyntaxPalette` 的公共 API 与暗色配色**，仅把手写分词器替换为 `highlight.parse`，自行把 `Node` 树映射为 `TextSpan`，并沿用现存的 composition 合成下划线逻辑。对 `wenz_rich_text_editor.dart` 的 `_codeSpan()` / `_darkCodeSyntaxPalette()` 调用方零改动。
