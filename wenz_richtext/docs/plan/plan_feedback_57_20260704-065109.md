# 反馈 #57 开发计划：标题块折叠大纲按钮不见了

## 需求描述

反馈 #57 指出：「标题块折叠大纲按钮不见了」——标题块左侧用于折叠/展开大纲的按钮（`_HeadingCollapseButton`）在编辑器中不再可见。这是一个功能回归：标题折叠（heading collapse / outline fold）特性此前已经实现并被测试与 golden 快照锁定（相关测试与 golden 均引用了上一轮计划的 P001/P002 修复），当前在InProgress 的大规模编辑器重构（`wenz_rich_text_editor.dart` 单文件 740 行 diff）过程中按钮再次消失。

## 项目分析

标题折叠按钮的渲染链路与回归可疑点全部位于编辑器渲染层，关键位置：

- `lib/src/widgets/wenz_rich_text_editor.dart`
  - `_hasHeadingCollapseChrome`（约 1988 行）：要求 `outlineController != null && identical(outline.editor, widget.controller)`，否则整条链路直接关闭——这是首要排查点。
  - `_headingCollapseStateFor(block)`（约 1993 行）：当 outline 已挂载且 block 为 `TextBlockNode(type == BlockType.heading)` 时，通过 `outline.collapseStateForBlockId(block.id)` 取状态。当前 working copy 已移除 `!state.canCollapse` 早返回（P001 修复），对所有标题块都返回状态（叶子标题返回 `canCollapse=false` 的禁用按钮）。
  - `_handleHeadingCollapseToggled`（约 2015 行）调用 `widget.outlineController?.toggleBodyHeadingByBlockId(blockId)`。
  - 虚拟列表 `itemBuilder`（约 2156–2183 行）把 `reserveHeadingCollapseRail: _hasHeadingCollapseChrome`、`headingCollapseState: _headingCollapseStateFor(block)`、`onHeadingCollapseToggled` 透传给 `_KeepAliveBlock` → `_BlockDragHandleOverlay`。
  - `_BlockDragHandleOverlayState.build`（约 6643 行）：`showHeadingCollapse = widget.headingCollapseState != null`（6649 行）；当 `!showDragHandle && !showHeadingCollapse` 时直接 `return widget.child`（6651 行），不再包裹任何 chrome。按钮本体在 6720–6738 行通过 `PositionedDirectional` + `OverflowBox(maxWidth: 0, alignment: centerEnd)` 浮在 gutter 上方，依赖外层 `Stack(clipBehavior: Clip.none)`（6691–6692 行）保证溢出可见。
  - `_HeadingCollapseButton`（约 8477 行）及其 glyph/tooltip（8597、8616 行），key 形如 `wenz-richtext-heading-collapse-<blockId>`。

- `lib/src/widgets/block_renderer_registry.dart`：`HeadingCollapseState`（约 428 行）及 `BlockRenderContext.headingCollapseState` 字段（约 402 行）是展示层契约；本文件本次仅有 16 行改动，疑似与对象块相关，但仍需核对未误伤标题块渲染上下文。

- `lib/src/controller/outline_controller.dart`：`collapseStateForBlockId`（611 行）提供折叠状态来源。

- 宿主接线：`example/lib/main.dart` 在 641、676 行传入 `outlineController: _outline`，`_outline` 由 bootstrap 提供（471 行）——需确认重构后宿主仍正常接线。

- 已有测试/快照：
  - `test/widgets/wenz_rich_text_editor_test.dart` 中 collapse 相关用例集中在 2425–3110 行（含 `renders heading collapse affordance and toggles by keyboard`、`renders all blocks without a collapse button when no outline`、`read-only heading collapse: button visible`、OverflowBox 定位断言等）。
  - `test/widgets/editor_golden_test.dart` 中 489–524 行（可编辑模式折叠按钮 golden）与 1184–1286 行 `editor_readonly_heading_collapse.png`。

回归最可能的根因（P001 需逐一验证后定论）：
1. 重构后 `_BlockDragHandleOverlay` 不再被应用到标题行（例如虚拟列表/`_KeepAliveBlock` 的包裹条件变更，或在 `showDragHandle==false` 的只读/无手柄路径下提前返回裸 child），导致 `showHeadingCollapse` 即使为 true 也不会进入按钮分支。
2. `OverflowBox(maxWidth:0)` 浮动定位或 `headingCollapseStart`/`activeChromeWidth`（6658–6669 行）计算被重构改动，使按钮被定位到视口外或被某个新加入的、非 `Clip.none` 的祖先裁剪。
3. outline 接线在重构中被破坏（`_hasHeadingCollapseChrome` 因 `identical(outline.editor, controller)` 不再成立而返回 false，或宿主停止传入 `outlineController`）。
4. `_headingCollapseStateFor` 的返回值在某个中间层（`_KeepAliveBlock` / overlay 构造）被丢弃或重置为 null。
