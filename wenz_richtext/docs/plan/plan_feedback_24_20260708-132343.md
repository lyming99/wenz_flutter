# 修复内存复制粘贴图片尺寸识别与显示比例

## 需求概要

根据反馈 #24，内存复制粘贴图片在进入编辑器后存在尺寸识别缺失或不准确的问题，导致 ImageBlockNode 无法携带真实像素宽高，默认图片块布局退回占位比例或错误比例，最终出现图片显示被错误约束、左右两侧留白等问题。项目中外部图片剪贴板读取集中在 lib/src/input/external_image_clipboard_reader.dart，内存图片落盘与描述生成在 lib/src/input/external_image_store_io.dart，图片块创建在 lib/src/input/clipboard_service.dart，显示比例计算在 lib/src/widgets/wenz_rich_text_editor.dart 的 _ImageDisplayMetrics/_imageAspectRatio。计划应补齐内存图片真实尺寸提取、描述到 ImageBlockNode 的宽高透传，并用输入层、剪贴板层和 widget 层场景防止比例回退。

## 任务拆解

- [x] P001: 为外部图片描述补充真实像素尺寸 <!-- scope: lib/src/input/external_image_input.dart,lib/src/input/external_image_store_io.dart,lib/src/input/external_image_store_stub.dart -->
  - 验收要点：内存图片候选在 prepare 成功后生成的 ExternalImageBlockDescription 能携带真实像素 width 和 height，尺寸来源于图片字节本身而不是剪贴板文件名、MIME 类型或临时文件路径推断。
  - 验收要点：PNG、JPEG、WebP、GIF、BMP 等当前支持的内存图片类型在可解码时都能得到正数尺寸；解码失败、空数据、损坏字节或平台不支持时不抛出未捕获异常，并保持现有失败或降级路径。
  - 验收要点：内存图片写入临时文件的文件名、扩展名、caption、altText 和字节内容不因尺寸提取而改变。
  - 验收要点：文件路径和 file:// URI 图片继续沿用现有文件校验与 canonical path 行为；如同步补充文件图片尺寸，应只在可安全读取时写入，不能破坏缺失文件、目录、空文件和不支持类型的拒绝原因。
- [x] P002: 将外部图片尺寸透传到粘贴生成的图片块 <!-- scope: lib/src/input/clipboard_service.dart,lib/src/controller/wenz_rich_text_controller.dart -->
  - 验收要点：ClipboardService.parseExternalImages 根据 ExternalImageBlockDescription 创建 ImageBlockNode 时保留真实 width 和 height，使后续渲染能够按原图比例计算。
  - 验收要点：内存图片粘贴生成的 ImageBlockNode 继续保留 file、caption、altText、自动生成 id 和 blocks paste 结构，且多张图片的插入顺序与现有行为一致。
  - 验收要点：没有可用尺寸的外部图片仍可按现有逻辑插入，不应因为 width 或 height 缺失而被过滤掉。
  - 验收要点：showWidth 和 showHeight 仍表示用户调整后的显示尺寸，首次粘贴不应把原始像素尺寸误写为 showWidth/showHeight，从而避免影响后续手动缩放语义。
  - 验收要点：粘贴到普通文本、对象块后方、表格单元格等现有插入位置策略保持不变。
- [x] P003: 确保图片块按真实比例约束默认显示框 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart,lib/src/widgets/media_resolver.dart -->
  - 验收要点：图片块存在原始 width 和 height 时，_ImageDisplayMetrics/_imageAspectRatio 优先按该比例计算显示框宽高，不再回退到占位 2:1 比例导致左右留白或比例压缩。
  - 验收要点：超宽、超高、小图和大图都经过现有最小宽度、最大宽度、比例上下限和可用宽度约束处理，显示框尺寸保持有限且不会溢出编辑器内容区域。
  - 验收要点：没有真实 width/height 的旧数据、空图片占位、加载失败占位继续使用现有占位比例和空状态视觉，不引入布局抖动。
  - 验收要点：已设置 showWidth/showHeight 的图片仍以用户调整后的显示尺寸为准，拖拽缩放后写回的宽高和撤销/重做行为不退化。
  - 验收要点：注入 MediaResolver 的图片仍被包裹在同一有限比例框内，resolver 返回的 Image/File/Network widget 不会因为外层比例错误产生额外左右空白。
- [x] P004: 补齐内存图片粘贴尺寸场景覆盖 <!-- scope: test/input/external_image_input_test.dart,test/input/clipboard_service_test.dart,test/widgets/wenz_rich_text_editor_test.dart,test/widgets/media_resolver_test.dart -->
  - 验收要点：输入层场景覆盖内存图片字节 prepare 后输出真实 width/height，并验证 caption、altText、临时文件扩展名和原始字节保持正确。
  - 验收要点：剪贴板服务场景覆盖 ExternalImageBlockDescription 的 width/height 被写入 ImageBlockNode，且无尺寸描述仍能生成可插入图片块。
  - 验收要点：编辑器粘贴场景覆盖 Ctrl/Cmd+V 读取内存图片 flavor 后插入的 ImageBlockNode 具备真实宽高，plain text fallback 不会在图片成功插入时额外插入。
  - 验收要点：显示层场景覆盖非 2:1 内存图片按真实比例生成图片 frame，避免用占位比例导致左右留白；同时覆盖旧数据无尺寸时仍走占位比例。
  - 验收要点：现有外部图片优先级、混合内存/文件图片顺序、失败回退到文本、关闭 external image input、rich Wenz JSON 优先级等场景不被本次修复破坏。
- [x] P005: 同步外部图片输入尺寸契约文档 <!-- scope: docs/input_system.md,docs/integration_guide.md,docs/api_reference.md -->
  - 验收要点：外部图片输入文档说明内存剪贴板图片会尽量提取真实像素 width/height，并通过 ExternalImageBlockDescription 进入图片块模型。
  - 验收要点：文档明确 width/height 是原图固有尺寸，showWidth/showHeight 是用户调整后的显示尺寸，两者语义不可混用。
  - 验收要点：宿主自定义 ExternalImageStore 的说明补充：如果业务层自行 materialize 图片，应在可获得时提供真实尺寸，无法获得时可留空并由编辑器使用兼容回退。
  - 验收要点：文档不改变外部图片启用开关、剪贴板读取优先级、文件路径/URI 图片校验和 MediaResolver 自定义渲染的现有说明。
