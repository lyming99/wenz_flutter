# 开发计划 #45：表格 Cell 矩形范围选择逻辑修复

> 反馈来源：反馈 #45
> 日期：2026-07-04
> 反馈摘要：表格选择逻辑有问题，选择表格 cell 算法应该选择开头结尾矩形范围内的表格 cell，使用 min(x), min(y), max(x), max(y) 计算矩形包围盒。

---

## 需求分析

### 问题描述

当前表格 cell 选择逻辑可能存在以下问题：
1. 当用户在表格内跨 cell 拖拽选择时，选中的 cell 范围未正确按矩形包围盒 (bounding box) 计算 —— 即应取 `min(startRow, extentRow)`、`max(startRow, extentRow)`、`min(startColumn, extentColumn)`、`max(startColumn, extentColumn)` 作为选中矩形区域；
2. 某些代码路径可能直接使用 `DocumentSelection.base` / `DocumentSelection.extent` 的原始行列值而没有通过 `tableCellRange` getter 做 min/max 归一化；
3. 表格 cell 高亮渲染逻辑 `_shouldHighlightTableCell` 依赖 `tableCellRange`，但跨 cell 拖拽时若 extent 未正确解析到目标 cell 的 row/column path，则不会产生矩形范围高亮。

### 已有分析结论

1. **`DocumentSelection.tableCellRange` (L267-290)** 已正确使用 `baseRow < extentRow ? baseRow : extentRow` 等 min/max 逻辑，算法方向正确；
2. **`MergeTableCellsCommand.execute` (L503-506)** 已内联 `top/bottom/left/right` 的 min/max 计算；
3. **`_currentTableRange` (L3796-3830)** 在构造 `TableCellRange` 时已使用 `math.min`/`math.max`；
4. **潜在风险点**：`_shouldHighlightTableCell` 中的跨 block 选择分支 (L10189-10198) 使用 `selection.start`/`selection.end` + `path.compare`，未经过 `tableCellRange` 的矩形归一化处理，在跨 table cell 选择时可能产生不正确的高亮判断。

## 总体验收标准

| 维度 | 标准 |
|------|------|
| `tableCellRange` 矩形计算 | base/extent 行列互换时，`startRow`≤`endRow`、`startColumn`≤`endColumn` 恒成立 |
| 跨 cell 拖拽高亮 | 从任意 cell 拖到任意 cell，高亮覆盖 min/max 矩形区域内所有非 covered cell |
| 反向拖拽 | 从右下角向左上角拖拽，选中范围与正向拖拽一致 |
| 合并 cell 操作 | `MergeTableCellsCommand` 接收的 startRow/startColumn 始终 ≤ endRow/endColumn |
| 工具栏状态 | `_collectTableCellStyle` 的 `TableCellRange` 始终为归一化后的矩形 |
| 回归 | 所有已有测试通过，无新增失败 |
