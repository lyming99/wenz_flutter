# 需求开发计划：设计标准对外接口，方便外部接入编辑器

## 来源

## 原始内容
请设计一个标准的对外接口，方便外部接入编辑器

## 需求理解
- “标准对外接口”指给外部业务方提供一套稳定、收敛、可文档化的接入面，让接入方无需了解内部六七个注册表与控制器的拼装顺序即可跑通“建实例 → 渲染编辑器 → 读写数据 → 扩展能力 → 销毁”的完整链路。
- 当前公共面是发散的：`lib/wenz_richtext.dart` 直接 re-export 了约 50 个内部文件，稳定性靠库头注释里的 tier 1/2/3 文字约定，没有程序化边界；接入方（见 `example/lib/main.dart`）需要手工创建 `WenzRichTextController`、`BlockRendererRegistry` + `installDefaultRenderers`、`InlineEmbedRendererRegistry`、`SlashMenuRegistry`、`WenzToolbarItemRegistry`、`MediaResolver`、`EditorShortcutConfiguration`、`pasteTransformers`，并自行调用 `installWenzRichTextPlugins`、自行管理各 `ChangeNotifier` 的 dispose 顺序，门槛高、易错。
- 采用“门面 + 配置”方案落地标准对外接口，而不是替换现有 typed API：新增 `WenzEditorConfiguration`（集中所有宿主侧接入开关）与 `WenzEditorBootstrap`（按配置一次性装配 controller + 各注册表 + 插件、构建 `WenzRichTextEditor` widget、统一 dispose），作为唯一推荐入口；既有 `WenzRichTextController`、`WenzRichTextEditor`、各类 `Registry`、`WenzRichTextPlugin` 保持 tier 1/2 不变，供高级用法继续使用。
- 数据契约收敛到门面：`exportJson/importJson/importMarkdown/importHtml`、`toJson/toMarkdown/toHtml/toPlainText`、版本快照、`onChanged/onSelectionChanged/onCommandExecuted` 回调与 `WenzEditorPermission` 读写评权限策略，都通过配置注入并在门面上暴露统一入口，不新建序列化格式、不改文档模型与 codec。
- 扩展契约收敛到配置：自定义 `blockRenderers`/`blockEmbedRenderers`、`inlineEmbedRenderers`、`slashMenuItems`、`toolbarItems`、`shortcutConfigurations`、`pasteTransformers`、`plugins`（`WenzRichTextPlugin`/`WenzPluginBundle`）均通过 `WenzEditorConfiguration` 注入，门面内部复用 `installWenzRichTextPlugins` 与各 registry 的现有装配逻辑。
- 稳定边界：将门面 + 配置列为 tier 1（标准对外接口），在库头注释、`docs/api_reference.md`、新增的 `docs/integration_guide.md` 中明确“推荐入口 vs 高级扩展点 vs 内部实现”的分层；`src/` 仍视为内部，公共面只通过 `lib/wenz_richtext.dart` 出口，不引入新的运行期依赖（PDF/DOCX/player 等仍走 `WenzDocumentExporter`/`MediaResolver` 注入边界）。
- 本计划只产出 plan 与代码/文档/测试，不改变既有命令语义、schema、codec、selection 契约与 tier 1/2 已公开类型签名；既有 example 与 README 的旧写法在 P006 改为门面写法，作为可复制的接入样例。

- [x] P002: 新增 WenzEditorConfiguration 标准配置对象 <!-- scope: lib/src/integration/wenz_editor_configuration.dart,lib/wenz_richtext.dart -->
  - 验收要点：新增 `lib/src/integration/wenz_editor_configuration.dart`，定义 `@immutable` 的 `WenzEditorConfiguration`，集中宿主侧接入开关：初始 `document`/`selection`、`permission`（默认 `edit`）、`mediaResolver`、`richTextJsonCodec`/迁移注册表、`accessibility`、`plugins`（`WenzRichTextPlugin`/`WenzPluginBundle`）、`shortcutConfiguration`/宿主 shortcut、`pasteTransformers`、`onMentionTap` 与三个 controller 回调、是否启用内置 slash menu/find&replace/outline/autosave/stats/toolbar 派生控制器等开关。
  - 验收要点：提供合理的全部可选字段 + 命名参数默认值，做到“零配置即可创建一个可用编辑器”；提供 `copyWith` 以便分场景派生配置，且配置对象本身不持有 `BuildContext` 与可变资源（仅描述意图）。
  - 验收要点：配置不直接创建 controller 或 widget，不产生副作用，字段类型复用现有公开类型（`WenzEditorPermission`、`MediaResolver`、`EditorShortcutConfiguration`、`WenzRichTextEditorAccessibility`、`RichTextJsonCodec` 等）；在 `lib/wenz_richtext.dart` 导出该类型。

- [x] P003: 新增 WenzEditorBootstrap 门面装配核心与注册表 <!-- scope: lib/src/integration/wenz_editor_bootstrap.dart,lib/wenz_richtext.dart -->
  - 验收要点：新增 `lib/src/integration/wenz_editor_bootstrap.dart`，提供 `WenzEditorBootstrap.create(configuration)` 工厂，按配置创建 `WenzRichTextController`，并新建 `BlockRendererRegistry`（调用 `WenzRichTextEditor.installDefaultRenderers` 后按配置注册自定义 block/embed renderer）、`InlineEmbedRendererRegistry`、`SlashMenuRegistry`、`WenzToolbarItemRegistry`，按需创建 `ToolbarController`/`SlashMenuController`/`WenzFindReplaceController`/`WenzOutlineController`/`WenzDocumentStatsController`/`WenzAutoSaveController` 并暴露 getter。
  - 验收要点：在装配阶段调用 `installWenzRichTextPlugins`，传入由配置生成的 `WenzPluginContext`（controller + 各 registry + shortcut + pasteTransformers），使插件贡献的命令/中间件/渲染器/slash item/toolbar item/shortcut/paste transformer 通过门面统一生效；装配顺序与现有 example 一致，不重复注册默认项。
  - 验收要点：门面暴露统一数据 I/O：`controller` getter、`toJson/toMarkdown/toHtml/toPlainText`、`loadJson/tryLoadJson`（含 `legacy:true`）、`loadMarkdown/tryLoadMarkdown`、`loadHtml/tryLoadHtml`、`createVersionSnapshot/restoreVersionSnapshot`、`setSelection/requestFocus` 等委托方法，签名与 `WenzRichTextController` 现有契约一致，不发明新语义；在 `lib/wenz_richtext.dart` 导出该类型。

- [x] P004: 门面统一构建编辑器 widget 并管理生命周期 dispose <!-- scope: lib/src/integration/wenz_editor_bootstrap.dart,lib/src/widgets/wenz_rich_text_editor.dart -->
  - 验收要点：`WenzEditorBootstrap` 提供 `buildEditor({...可选外观参数})`（或等价 widget 工厂）返回 `WenzRichTextEditor`，统一注入 `controller`、`blockRenderers`、`mediaResolver`、`inlineEmbedRenderer`、`slashMenuController`、`findController`/`onFindRequested`/`onReplaceRequested`、`outlineController`、`onMentionTap`、`shortcutConfiguration`、`accessibility`，且允许接入方按需透传 `padding/blockSpacing/textStyle/defaultTextColor/physics/focusNode/autofocus/readOnly/showDebugOverlay/enableIme`。
  - 验收要点：`buildEditor` 不引入新的 widget 类型或主题对象，遵循 `WenzRichTextEditorAccessibility` + 主题 token 边界（不把主题写入文档模型），返回的 widget 行为与直接构造 `WenzRichTextEditor` 完全一致；只读/评论/编辑模式由配置 `permission` 透传到 controller，不绕过命令权限门。
  - 验收要点：`WenzEditorBootstrap.dispose()` 按依赖逆序释放各派生 controller 与注册表资源，保证 `SlashMenuController` 等监听编辑器的对象先于 `WenzRichTextController` 释放（与现有 example dispose 顺序一致），并避免重复 dispose；提供 `dispose` 幂等保护。

- 计划中的所有 checkbox 任务完成，每个任务的验收要点均有对应实现、测试或记录说明；`## 任务拆解` 为开发任务唯一来源，任务编号 P001→P008 连续不跳号。
