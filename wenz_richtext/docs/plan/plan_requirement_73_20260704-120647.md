## 背景与影响范围

本项目当前已经具备工具栏底层能力，但默认桌面端工具栏仍停留在示例应用私有实现层：

- `lib/src/controller/toolbar_controller.dart` 提供 `ToolbarController` / `ToolbarState`，覆盖 inline mark、链接、文字颜色、块类型、对齐、缩进、图片/视频插入、undo/redo、表格上下文状态等 headless 能力。
- `lib/src/controller/toolbar_controller.dart` 的 `WenzToolbarItem` / `WenzToolbarItemRegistry` 只作为插件或宿主贡献按钮的描述符；现有注释与 `docs/api_reference.md` 明确写着包内“不提供固定 toolbar widget”。
- `lib/src/integration/wenz_editor_bootstrap.dart` 默认会创建 `toolbarController` 和空的 `toolbarItemRegistry`，但没有 `buildToolbar` 一类的便捷入口；外部接入方只能自己写 UI 或复制 `example/lib/main.dart` 的私有 `_Toolbar`。
- `example/lib/main.dart` 的 `_Toolbar` 已经证明核心交互链路可行，但包含示例专属图片选择、CRM embed、流程图按钮、文案和私有 helper，不适合直接作为库 API 暴露。

本需求按“库内提供可直接使用的 Material 桌面工具栏，仍允许宿主定制资源型动作”的方向推进。默认工具栏应复用既有 `ToolbarController` 状态和命令入口，不改变文档模型、命令权限闸门、历史记录、插件注册顺序和编辑器渲染器。

## 实施策略

新增一个公开的桌面端默认工具栏 widget，建议命名为 `WenzDefaultDesktopToolbar`，放在 `lib/src/widgets/default_desktop_toolbar.dart`。它接收外部已拥有的 `WenzRichTextController`、`ToolbarController` 和可选 `WenzToolbarItemRegistry`，自身只负责渲染、状态绑定和调用既有命令，不创建或释放 controller。

无需业务资源的动作由库内直接提供默认实现，例如加粗、斜体、下划线、删除线、备注、颜色、清除样式、链接弹窗、标题/段落/引用/列表、对齐、缩进、撤销/重做、公式/emoji、代码块、提示块、表格和表格结构操作。图片、视频、文件、业务 embed 等资源型入口通过可选 callbacks 或 `WenzToolbarItemRegistry` 接入；未提供回调时应隐藏或禁用，不插入无效业务数据。

为了真正方便外部使用，在 `WenzEditorBootstrap` 上补一个便捷 builder，例如 `buildDefaultDesktopToolbar(...)`，直接使用 bootstrap 已组装好的 `controller`、`toolbarController` 和 `toolbarItemRegistry`。同时更新公开导出、文档和 example，让示例从复制版私有 toolbar 迁移到库内默认 toolbar。
