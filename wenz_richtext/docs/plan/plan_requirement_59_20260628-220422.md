# 需求 #59 开发计划：斜杆 popup 样式优化（Electron 风格）+ 中文化

- 需求编号：#59
- 创建日期：2026-06-28
- 状态：待评审

## 需求概述

针对富文本编辑器的斜杆（`/`）命令 popup，完成两件事：

1. **样式优化**：将 popup 外观改为 Electron 桌面端风格（如 VSCode / Cursor / Notion 桌面版的命令面板观感）—— 扁平、克制阴影、清晰层级、紧凑节奏。**先以 HTML 设计稿形式产出**，落地到 `ui/` 文件夹，再据稿实现。
2. **中文化**：popup 内所有面向用户的文案由英文改为简体中文（菜单项标题/描述、空状态、语义标签）。

## 现状分析（勘察结论）

- 外观实现集中在 `lib/src/widgets/slash_menu_overlay.dart`：
  - `WenzSlashMenuOverlay`：容器 chrome（`_slashMenuSurfaceColor` / `_slashMenuShape` / elevation=6 / 阴影 alpha=48 / 圆角=12）。
  - `_SlashMenuTile`：单项渲染（图标 + 标题 + 描述，选中态用 `primaryContainer` 低透明背景）。
  - `_SlashMenuEmptyState`：空状态，含英文文案 `'No commands found'` / `'Try a different keyword.'`，语义标签 `'No slash commands found'`。
- 菜单项数据集中在 `lib/src/controller/slash_menu_controller.dart` 的 `defaultSlashMenuItems()`，标题/描述均为英文（`Heading`、`Heading 2~6`、`Bulleted list`、`Todo`、`Quote`、`Code block`、`Table`、`Image`、`Video` 及对应 description），另有视频占位标题 `'Video placeholder'`。`id` 与 `keywords`（已含中文检索词）需保持不变。
- 项目**未引入 i18n / l10n**（无 `AppLocalizations`、无 `flutter_localizations`、无 `generate: true`），现有 UI 字符串均为硬编码。

## 方案与关键决策

1. **设计先行（design-first）**：先用 HTML 产出 Electron 风格设计稿（`ui/`），经确认后再据稿实现 overlay 样式，避免反复试错。
2. **Electron 风格要点（写入设计稿与规范）**：
   - 扁平化：弱化 elevation/阴影（更低 alpha、更收敛的模糊半径），保留克制的 1px `outlineVariant` 描边；圆角收敛（约 10~12px）。
   - 层级清晰：图标位 + 标题（medium/semibold）+ 描述（更小、muted）；选中态采用低透明度强调色背景 + 强调色标题/图标。
   - 紧凑节奏：收紧容器与条目内边距、垂直间距。
   - 配色全部复用现有 `colorScheme` token（`surfaceContainerLow` / `outlineVariant` / `primary` / `primaryContainer` / `onSurfaceVariant`），不引入与主题冲突的硬编码色。
   - **可选**分组（section 标题）：作为增强项；若设计稿采用分组，则需在数据层补充分组字段。默认方案为“精修扁平列表”，避免无谓的 schema 改动。
3. **中文化方式**：沿用现有“硬编码字符串”模式，直接将英文字面量替换为简体中文；**不引入** i18n 框架（避免范围蔓延）。`id` / `keywords` 不变，保证既有集成、检索与拼音匹配不受影响。
4. **范围边界**：本计划仅改 popup 的**外观与文案**，不触碰 popup 的定位/锚点逻辑、触发逻辑、键盘事件路由等行为；不改菜单项的动作（`action`）。
