# 需求 #65 开发计划：编辑器内部标题块大纲折叠

> 需求原文：编辑器内部要支持大纲折叠，如果是标题类型的 block，左侧要有一个折叠/展开按钮，将子内容进行折叠。
>
> 目标：在编辑器正文区（非侧边大纲面板）为「标题类型」的块在左侧提供折叠/展开按钮；点击后折叠该标题下属的子内容（后续更低层级或同层级之前的兄弟块），再次点击展开；折叠为纯视图投影，不改动文档数据/选区/历史。本需求只覆盖「编辑器内部」的折叠交互，与右侧大纲树面板（需求 #64）解耦但共用同一份折叠状态。

## 背景与现状（基于现有代码）

> 重要：经核查，本需求对应的「编辑器内部标题折叠」能力在工作区中已**基本落地**（属于与需求 #58–#64 同批的未提交改动，`git status` 显示 `lib/src/widgets/wenz_rich_text_editor.dart` 为 modified）。因此本 plan 的开发任务以「补全 / 兜底 / 加固 / 测试」为主，每个任务的验收要点描述目标行为；执行时若发现对应代码已满足，则以核对+补缺为主，不重复造轮子。

- 折叠数据模型已就绪（`lib/src/controller/outline_controller.dart`）：
  - `OutlineItem.canCollapse`（= `collapseRange.isNotEmpty`）、`OutlineItem.isCollapsed`、`OutlineItem.hiddenBlockCount`。
  - `OutlineBlockProjection`（含 `visibleBlocks`、`visibleBlockIndexes`、`hiddenBlockIds`、`hiddenBlockCount`、`hasHiddenBlocks`、`isBlockHidden/isBlockIndexHidden`），由 `WenzOutlineController.visibleBlockProjection()` 经 `OutlineBlockProjection.fromCollapsedItems(...)` 派生。

  - `WenzOutlineController` 是 `ChangeNotifier`，编辑器通过 `addListener` 订阅折叠态变化。

- 编辑器接线已落地：`WenzRichTextEditor.outlineController` 入参；`_handleOutlineControllerChanged` 监听；`_headingCollapseStateFor(block)` 按块派生 `HeadingCollapseState`；`_handleHeadingCollapseToggled(blockId)` → `outlineController.toggleByBlockId`；`build()` 中 `_visibleBlockProjectionFor(sourceBlocks)` 投影可见块；折叠仅作用于渲染（源文档顺序/id/索引/编解码/历史不变，见 `:1758` 注释）。
- 已有测试覆盖：`test/controller/outline_controller_test.dart`、`test/widgets/wenz_rich_text_editor_test.dart`、`test/widgets/editor_golden_test.dart` 均含折叠相关用例（grep 命中 `HeadingCollapse` / `visibleBlockProjection` / `toggleByBlockId` / `wenz-richtext-heading-collapse`）。
- 缺口 / 待确认：
  1. example 当前 `WenzEditorBootstrap.create(..., enableOutline: false, ...)`（`example/lib/main.dart:297`），**未把 `outlineController` 接给编辑器**，故编辑器内折叠按钮在 example 中尚不可见/不可操作（该项与需求 #64 的 example 接线 P004 重叠，本 plan 在验收节点以「开启大纲后」为前置条件做目测）。
  2. 边界场景需核对：无子内容的叶子标题（`canCollapse == false`）按钮态、折叠态被删标题后的集合收敛、嵌套标题折叠范围、空标题不作为折叠目标、折叠区内有选区/插入点时的自动展开、`keepAlive`/虚拟化下隐藏块的卸载一致性。
  3. 编辑器内折叠的组件级测试是否覆盖「点击按钮 → 子块隐藏 → 再点 → 恢复」「徽标隐藏块数」「键盘激活」需确认补齐。

## 设计决策（关键取舍）

1. **折叠状态单一事实来源 = `WenzOutlineController`**：编辑器内按钮与右侧大纲树（#64）共用同一控制器与 `_collapsedBlockIds`，二者任意一方折叠都双向反映；编辑器内部按钮只是 `toggleByBlockId(blockId)` 的另一个触发入口，不引入第二份折叠状态。
2. **折叠为视图投影、零数据改动**：`OutlineBlockProjection` 只影响 `build()` 渲染的可见块列表；源 `document.blocks`、block id/index、编解码、撤销栈一律不变（已由 `:1758` 注释约束）。新增/重做任务必须维持该不变量。
3. **按钮仅在「标题块 + 有可折叠子内容」时可用**：叶子标题（折叠范围为空）按 disabled/不响应处理（`canCollapse == false`），避免出现「点了没反应」的折叠按钮；空标题行不进入折叠目标集（控制器已过滤）。
4. **可访问性与命中区**：按钮需键盘可达（Enter/Space）、有 tooltip，并通过 `BlockGeometryRegistry.registerSelectionExclusion` 排除出正文选区命中，防止误触发跨块选区/光标移动。
5. **不把「运行测试/分析/example 目测」拆成普通开发任务**：统一收敛到最后的「完整验收」节点。
6. **与需求 #64 的边界**：本 plan 不负责「右侧大纲树面板」本身，仅在验收节点以「example 开启大纲（依赖 #64）」为前置做集成目测；折叠的库内能力与测试由本 plan 负责。

## 任务拆解

- [x] P001: 确保标题折叠范围与可见块投影正确 <!-- scope: lib/src/controller/outline_controller.dart -->
  - 核对 `_collapseRangeForHeading(...)`：H1–H6 各级标题的覆盖区间应到「下一个同级或更高级标题」之前（不含该标题自身），末尾标题折叠到文档末尾；嵌套标题（如 H1 内含 H2）折叠范围不越级。
  - 核对 `OutlineBlockProjection.fromCollapsedItems(...)` 与 `visibleBlockProjection()`：被折叠标题的子块进入 `hiddenBlockIds`/`hiddenBlockIndexes`，`visibleBlocks` 顺序与源文档一致且保留原 block id/index；`OutlineBlockProjection.all(...)` 在无折叠时原样返回全量。
  - 核对折叠集合收敛：标题被删除/降级/清空后，其 id 从 `_collapsedBlockIds` 移除（`_recompute` 已 `where(collapsibleIds.contains)`）；空标题、非标题块不作为折叠目标。
  - 核对选区联动：选区/插入点落在折叠区间内时 `expandToRevealSelection` / `expandToRevealBlockId` 能展开对应标题使目标块可见。

- [x] P002: 标题块左侧渲染折叠/展开按钮并切换 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart, lib/src/widgets/block_renderer_registry.dart -->
  - 仅当 `block.type == BlockType.heading` 且存在非空 `headingCollapseState` 时渲染左侧折叠槽（约 `:6362`），其余块不预留该槽、不偏移正文。
  - 按钮态：`canCollapse == true` 时可点击；展开态显示向下箭头，折叠态显示向右箭头并叠加 `_HeadingCollapseCountBadge`（隐藏块数，>99 显示 `99+`）。
  - 叶子标题（`canCollapse == false`）按钮置为 disabled 或不响应，tooltip 文案区分「无可折叠内容 / 折叠 / 展开」。
  - 可访问性：按钮带稳定 `ValueKey('wenz-richtext-heading-collapse-{blockId}')` 与 tooltip；Enter/Space/小键盘 Enter 可触发切换；通过 `BlockGeometryRegistry.registerSelectionExclusion` 排除出正文选区命中区，切换后焦点回到按钮（`_toggle` 已含 `addPostFrameCallback` 重聚焦）。
  - 主题：明/暗主题下按钮、徽标配色正常（沿用 `colorScheme`，不硬编码颜色）。
