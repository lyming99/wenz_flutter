# 优化文字颜色工具栏入口与宫格色板选择

## 需求概要

根据反馈 #22，默认工具栏需要把独立的“无文字颜色/清除文字颜色”按钮收敛到“文字颜色”下拉 popup 内，减少工具栏横向溢出；同时将桌面端文字颜色 popup 从纵向列表改为宫格色板，并通过 tooltip 展示颜色名称、当前颜色和清除颜色等状态。项目现有文字颜色状态与命令已集中在 ToolbarController 和 WenzRichTextController，预计不需要改动核心命令，只需调整 lib/src/widgets/default_desktop_toolbar.dart 的桌面工具栏 UI，并补齐默认桌面/移动工具栏相关 widget 测试；移动端当前已是 Wrap 色板，但 tooltip 仍为泛化“文字颜色”，应同步补齐颜色级 tooltip 一致性。

## 任务拆解

- [x] P001: 将桌面端清除文字颜色按钮合并进文字颜色 popup <!-- scope: lib/src/widgets/default_desktop_toolbar.dart -->
  - 验收要点：桌面默认工具栏主按钮序列中不再渲染独立的“无文字颜色/清除文字颜色”图标按钮，文字颜色相关入口只保留“文字颜色”下拉按钮。
  - 验收要点：文字颜色 popup 内提供清除文字颜色入口，沿用 toolbar.clearTextColor 行为，并在无颜色、已有颜色、混合颜色和不可编辑状态下保持正确启用、禁用与提示语。
  - 验收要点：合并后清除文字颜色仍只清除 inline font color，不影响加粗、斜体、链接、块样式、对齐等其他格式。
  - 验收要点：工具栏窄宽度横向布局减少一个按钮宽度，现有滚动溢出机制、按钮间距和分组分隔保持稳定。
- [x] P002: 将桌面端文字颜色 popup 改为宫格色板 <!-- scope: lib/src/widgets/default_desktop_toolbar.dart -->
  - 验收要点：内置文字颜色选项不再以 MenuItemButton 纵向文字列表展示，而是以宫格色块展示，色块使用现有 _kTextColorOptions 的颜色值和标签。
  - 验收要点：每个色块提供 tooltip，能展示对应颜色名称和十六进制颜色值，用户无需依赖列表文字识别颜色。
  - 验收要点：当前选中的内置颜色在宫格中有清晰选中态；混合颜色、自定义颜色和无颜色状态不会误标某个内置色块为选中。
  - 验收要点：色板在 popup 宽度内按固定尺寸和间距换行，不因 tooltip、选中图标或 disabled 状态导致布局抖动、重叠或溢出。
  - 验收要点：popup 继续保留自定义颜色入口，且自定义颜色输入、当前自定义颜色展示和选择后工具栏图标染色行为保持可用。
- [x] P003: 统一移动端颜色色板 tooltip 表达 <!-- scope: lib/src/widgets/default_mobile_toolbar.dart -->
  - 验收要点：移动端颜色面板继续使用现有宫格式 Wrap 色块，不退化为列表选择。
  - 验收要点：移动端每个颜色色块 tooltip 从泛化“文字颜色”调整为包含具体颜色名称和颜色值的提示，便于区分不同色块。
  - 验收要点：移动端清除文字颜色按钮 tooltip 能表达清除当前颜色、清除混合颜色或无文字颜色状态，并与桌面端语义保持一致。
  - 验收要点：移动端已选颜色、混合颜色、无颜色和只读/不可编辑状态下，色块选中态、禁用态和触发命令行为保持正确。

  - 验收要点：移动端测试覆盖颜色色块 tooltip 具体化、清除颜色 tooltip 状态，以及窄宽度下面板 Wrap 不产生 framework overflow。
  - 验收要点：测试断言不依赖纵向列表文字项来选择内置颜色，避免实现回退为列表后仍然误通过。
