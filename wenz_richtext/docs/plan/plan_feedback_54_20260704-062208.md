# 反馈 #54 开发计划：折叠大纲按钮可见性修复与间距调整

## 需求描述

> 折叠大纲按钮不见了：应该放到块操作按钮右边，水平间距4dp

当前问题：在上一次提交（编辑器优化）中，`_headingCollapseStateFor()` 方法新增了 `if (state == null || !state.canCollapse) { return null; }` 检查，导致没有折叠子块内容的 heading（`canCollapse == false`）不再渲染折叠按钮。此前这些 heading 会显示**禁用态**折叠按钮（tooltip 显示"无可折叠内容"），现在按钮完全消失。

同时，当前折叠按钮与左侧拖拽 handle 之间的间距使用 `BlockDragHandleSpec.chromeGap = 8dp`，需要改为 **4dp**。

## 技术分析

### 关键代码路径

```
_WenzRichTextEditorState._headingCollapseStateFor(block)
  ↓ 调用 outline.collapseStateForBlockId(block.id)
  ↓ 返回 OutlineCollapseState?（含 canCollapse、isCollapsed、hiddenBlockCount）
  ↓ 旧行为：总是返回 HeadingCollapseState（canCollapse 可能为 false → 按钮禁用态）
  ↓ 新行为：canCollapse==false 时返回 null → 按钮隐藏
  ↓ 传递到 _BlockRenderer → _BlockDragHandleOverlay.headingCollapseState
  ↓ showHeadingCollapse = headingCollapseState != null → false → 按钮不渲染
```

### 涉及常量

| 常量 | 当前值 | 说明 |
|------|--------|------|
| `BlockDragHandleSpec.chromeGap` | 8.0 | 拖拽 handle 与折叠按钮间距（需改为 4dp） |
| `BlockDragHandleSpec.hitSize.width` | 28.0 | 拖拽 handle 宽度 |
| `_kHeadingCollapseButtonSize` | 24.0 | 折叠按钮尺寸 |
| `_kHeadingCollapseIconSize` | 18.0 | 折叠箭头图标尺寸 |
| `_kHeadingCollapseSlotWidth` | 24.0 | 折叠按钮槽位宽度 |

### 修复方案

**P001 — 恢复折叠按钮可见性:**

修改 `_headingCollapseStateFor()` 逻辑：当 `collapseStateForBlockId` 返回非 null 时（即 heading 存在于 outline 中），始终构建 `HeadingCollapseState`，`canCollapse` 字段如实反映是否能折叠。只有 `collapseStateForBlockId` 返回 null（heading 未注册到 outline）时才隐藏按钮。

**P002 — 调整间距为 4dp:**

在 `_BlockDragHandleOverlayState.build()` 中将 `headingCollapseStart` 计算中的 `BlockDragHandleSpec.chromeGap`（8dp）替换为新增常量 `_kHeadingCollapseGap`（4dp）。该常量仅用于 heading 折叠按钮与 drag handle 之间的间距，不影响 `chromeGap` 在其他上下文的语义。

**P003 — 补充测试:**

为折叠按钮可见性逻辑补充测试用例，覆盖以下场景：
- 有子块待折叠的 heading：按钮可见且可点击
- 无子块的 heading（canCollapse==false）：按钮可见但禁用
- 非 heading block：按钮不渲染
- 无 outlineController 时：按钮不渲染

**P004 — Golden 测试更新:**

修改 `chromeGap` 间距后，heading 行的 golden 截图需要更新。
