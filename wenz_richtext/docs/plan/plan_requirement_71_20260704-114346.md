## 背景与影响范围

需求要求图片不再提供“创建块副本”能力，并且图片本身支持通过边缘拖拽调节 size，拖拽时按比例缩放。基于当前代码分析，图片块已经具备持久化显示尺寸字段：

- `ImageBlockNode` 已有 `showWidth/showHeight`，JSON、HTML、Markdown 相关 codec 已能保存和恢复尺寸。
- `WenzRichTextController.updateImageBlock` 与 `UpdateImageBlockCommand` 已能修改图片尺寸，并参与 undo/redo、权限 gate 和变更通知。
- 图片渲染集中在 `lib/src/widgets/wenz_rich_text_editor.dart` 的 `_ImageBlockContent`、`_MediaBlockChrome`、`_ObjectMoreMenu` 与 `_handleObjectBlockAction`。
- 图片对象工具栏当前提供“图片宽度：小/中/大”“重置图片尺寸”，同时图片更多菜单和左侧块操作菜单仍会出现“创建块副本”。
- 现有测试覆盖图片工具栏定位、固定宽度菜单、重置尺寸、媒体选中描边和 controller 更新尺寸，适合作为本需求的增量测试基础。

## 实施策略

保持文档模型和既有 command pipeline 稳定，复用 `showWidth/showHeight` 作为图片显示尺寸的唯一持久化字段。拖拽过程在 widget 层维护临时预览尺寸，只在拖拽结束时提交一次 `updateImageBlock`，避免每一帧写入历史栈。比例计算优先使用图片原始 `width/height`，缺失时退回当前显示 frame 的实际宽高。图片的“创建块副本”需要从图片相关 UI 入口移除，并在 action handler 层增加防御，避免自定义入口或旧菜单仍能复制图片块。
