# 反馈 #16 开发计划：修复 example Windows 构建依赖解析失败

## 背景

反馈 #16 报告在 `example` 目录执行 `flutter run -d windows` 时编译失败，错误集中在两类：

1. **依赖解析失败**：`Couldn't resolve the package 'super_clipboard'` / `super_drag_and_drop`，以及由此级联产生的 `Formats` / `DataFormat` / `FileFormat` / `DropOperation` / `DropRegion` 未定义错误，全部位于 `lib/src/widgets/wenz_rich_text_editor.dart`。
2. **listEquals 未定义**：`example/lib/flowchart/flowchart_view.dart` 第 133/134/556 行 `listEquals` 不被识别。
3. 末尾 `MSB8066` 自定义生成退出码 1，构建过程整体失败。

## 根因分析

经核查代码与构建状态：

- `super_clipboard: ^0.9.1` 与 `super_drag_and_drop: ^0.9.1` 是本次相对 HEAD **新增**到根 `pubspec.yaml` 的依赖（`git diff HEAD` 显示为新增行）。
- `pubspec.lock` / `example/pubspec.lock` 均已锁定 `0.9.1`；`example/.dart_tool/package_config.json`（mtime 晚于 pubspec，非过期）已正确注册这两个包。
- pub cache 中 `super_clipboard-0.9.1` / `super_drag_and_drop-0.9.1` 完整（含 `lib/super_clipboard.dart` / `lib/super_drag_and_drop.dart`，分别为 17 / 10 个 dart 文件）。
- `example/windows/flutter/generated_plugins.cmake` 已包含原生后端 `super_native_extensions` 与 `irondash_engine_context`（super_clipboard / super_drag_and_drop 在 Windows 上无独立 CMake 插件，依赖这两个 FFI 后端）。
- super_clipboard 0.9.1 的 SDK 约束 `>=3.0.0 <4.0.0`，与 example 的 `sdk: ^3.11.0` 兼容；`pub get` 层面解析成功。
- `lib/src/widgets/wenz_rich_text_editor.dart` 对 0.9.1 的 API 用法（`Formats.png/jpeg/gif/webp/fileUri`、`DataFormat<Object>`、`FileFormat`、`DropOperation`、`DropRegion`）正确；`example/lib/flowchart/flowchart_view.dart` 顶部已 `import 'package:flutter/foundation.dart';`（`listEquals` 来源）。

**结论**：依赖在 pub 层面（lock / package_config / pub cache / 插件注册）均已就绪且正确，源码用法亦正确。报错发生在 `flutter_assemble.vcxproj` 的 CUSTOMBUILD（CMake / Dart 编译）阶段，根因是 **Windows 构建产物陈旧**——`example/build/windows/` 中 CMake / kernel 缓存早于依赖新增，增量构建未能重新解析包，导致构建期 Dart frontend 找不到包，并级联产生 `listEquals`（来自 foundation，包解析降级时其导出符号不可见）等符号未定义错误。

修复主线为 **构建清理 + 重新解析 + 全量重建**；源码原则上无需改动，但按错误簇保留逐项校验 / 兜底任务，确保任意真实 API 偏差都能在对应文件定位修正。
