# 需求 #11 开发计划：引用文本样式与复合块支持

## 需求理解

当前项目已存在 `BlockType.quote`、`_QuoteBlockSurface`、连续引用块视觉融合、slash 菜单“引用”、Markdown `>` 快捷转换、HTML/Markdown/PlainText 编解码，以及多组引用渲染测试。现有模型中 `BlockType.quote` 与 `BlockType.heading`、`BlockType.listItem` 等是互斥类型，因此“引用内容也可以是标题、todo、列表、有序列表”等需求需要把“引用”从单一 block 类型能力扩展为可叠加的块级装饰状态，同时保留旧数据兼容。

本计划按最优工程方案推进：新增可叠加引用属性，渲染层统一以该属性或 legacy `BlockType.quote` 判断引用外观；样式命令、slash/Markdown 快捷入口只切换引用属性，不破坏标题、todo、无序/有序列表等原有语义；修复回车换行时引用背景短暂间距闪现，确保相邻引用行即时形成整体背景。

## 总体验收标准

1. 功能验收：引用文本不再表现为斜杆/斜线式样；引用背景在连续引用行之间从首帧起形成整体背景，不出现约 200ms 的临时间距闪现。
2. 组合验收：引用可与标题、todo、无序列表、有序列表、有序 todo 等文本块语义同时存在；执行引用/取消引用不丢失原 block 类型、level、listType、checked、indent、alignment。
3. 兼容验收：旧文档中的 `BlockType.quote`、Markdown `>`、HTML `blockquote`、现有 JSON 数据仍能正常加载和导出；新引用属性能稳定 round-trip。
4. 渲染验收：连续引用组只在相邻引用文本块之间融合；引用与普通段落、标题、列表、代码、表格、媒体等非引用块相邻时仍保持正常块间距。
5. 自动化验收：执行 `dart format lib test example && flutter analyze && flutter test` 全部通过；涉及 golden 的视觉变化必须确认符合需求后更新基准图。
