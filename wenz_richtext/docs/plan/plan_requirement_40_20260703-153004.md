# 需求 #40 开发计划：编辑器左侧按钮与 Popup Chrome 优化

- 需求编号：#40
- 生成时间：2026-07-03 15:30:04
- 需求内容：编辑器左侧优化：折叠按钮不需要显示数字，要垂直居中行高；折叠按钮不存在时，块操作按钮在折叠按钮位置，自动靠右；优化一下块操作 popup，包括编辑器其它的 popup，要注意深浅色风格，chrome 风格；折叠按钮宽度尺寸小一些，外边距小一些。

## 背景与影响范围

当前编辑器左侧行级 chrome 主要由 `lib/src/widgets/wenz_rich_text_editor.dart` 中的 `_BlockDragHandleOverlay`、`_BlockDragHandleButton`、`_HeadingCollapseButton`、`_HeadingCollapseGlyph` 负责；公共行级规格在 `lib/src/widgets/block_renderer_registry.dart` 的 `BlockDragHandleSpec` 中定义。折叠按钮目前使用 `_kHeadingCollapseSlotWidth = 30.0`、`_kHeadingCollapseButtonSize = 26.0`、`_kHeadingCollapseIconSize = 20.0`，折叠后还会通过 `_HeadingCollapseCountBadge` 显示隐藏块数量；按钮与块操作按钮都使用 `BlockDragHandleSpec.topInset` 顶部锚定，未按行高垂直居中。

块操作 popup 和编辑器内多个 popup 已经集中使用 `wenz_rich_text_editor.dart` 的 `_kMinimalMenu*`、`_kPopupMenu*`、`_popupMenuColor`、`_popupMenuShape`、`_PopupMenuItemContent` 等 token/helper；`slash_menu_overlay.dart` 独立维护 slash menu chrome，并已参考 `docs/design/menu_toolbar_minimal_spec.md`。本需求应优先收敛这些 token，而不是在单个菜单项里散落颜色和尺寸。

主要影响文件预计为：

- `lib/src/widgets/wenz_rich_text_editor.dart`：左侧行级 chrome、折叠按钮、块操作菜单、公式 popup、代码语言菜单、表格 toolbar 菜单、对象块/文件块菜单。
- `lib/src/widgets/block_renderer_registry.dart`：`BlockDragHandleSpec` 的 rail、间距和命中尺寸契约。
- `lib/src/widgets/slash_menu_overlay.dart`：slash popup 与编辑器 popup 的深浅色、阴影、边框、圆角和紧凑节奏一致性。
- `docs/design/menu_toolbar_minimal_spec.md`：如实现中调整公共 token，需同步更新设计约束说明。
- `test/widgets/wenz_rich_text_editor_test.dart`、`test/widgets/editor_golden_test.dart`、`test/widgets/slash_menu_overlay_test.dart`：补充或更新左侧布局、数字 badge 移除、popup 样式与深浅色覆盖。

## 实施策略

采用“先规格、再布局、再 popup、最后测试”的方案。左侧按钮先统一为内容边缘附近的行级 chrome slot：折叠按钮存在时占用靠内容侧的折叠 slot，块操作按钮在其左侧；折叠按钮不存在时，块操作按钮自动移动到同一个靠内容侧 slot，并在 rail 内靠右对齐。折叠按钮移除可见数字 badge，但保留 controller 的 `hiddenBlockCount` 语义，必要时仅用于 tooltip 或语义描述。

Popup 优化以现有 token/helper 为主入口，目标是 Chrome 风格的克制桌面浮层：浅色和深色都使用 `ColorScheme`，容器低饱和、弱阴影、细边框、紧凑圆角和菜单项节奏；对象块、行块操作、文件块、表格 toolbar、代码语言、公式 popup 与 slash menu 在视觉语言上保持一致，同时不改变菜单动作分发、键盘路由、定位和只读行为。

## 任务拆解

- [x] P001: 收敛左侧行级 chrome 规格与折叠按钮尺寸 <!-- scope: lib/src/widgets/block_renderer_registry.dart,lib/src/widgets/wenz_rich_text_editor.dart -->
  验收要点：
  - `BlockDragHandleSpec` 的 `railWidth`、`chromeGap`、`gapToContent`、`topInset` 等规格与新的左侧布局匹配，rail 宽度不再为了旧数字 badge 预留过多空间。
  - `wenz_rich_text_editor.dart` 中 `_kHeadingCollapseSlotWidth`、`_kHeadingCollapseButtonSize`、`_kHeadingCollapseIconSize` 调整为更小、更紧凑的尺寸，并同步 `WenzRichTextDesignBaseline.layoutTokens['headingCollapse']`。
  - 折叠按钮外边距和命中区域在不牺牲基本可点击性的前提下收紧，视觉上不再挤占正文内容宽度。
  - 改动不影响列表缩进、引用块宽度、代码块、表格、媒体块和自定义 block renderer 的内容起点。

- [x] P002: 调整折叠按钮与块操作按钮的定位行为 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  验收要点：
  - `_BlockDragHandleOverlay` 使用 Directional 布局计算左侧 chrome 位置，支持 LTR/RTL，且不改变正文内容的水平对齐。
  - 折叠按钮存在时，折叠按钮位于靠内容侧的紧凑 slot；块操作按钮位于折叠按钮左侧，并保持清晰间距。
  - 折叠按钮不存在时，块操作按钮自动占用折叠按钮位置，并在左侧 rail 内靠右贴近内容侧，而不是停留在旧 rail 最左端。
  - 折叠按钮和块操作按钮按首行/行高视觉中心垂直居中，不再使用固定顶部贴边效果；标题、段落、空标题、列表项等常见行高下中心对齐稳定。
  - selection exclusion、键盘焦点、hover、拖拽阈值、点击打开块操作菜单、折叠切换等既有交互保持可用。

- [x] P003: 移除折叠按钮可见数字并保留折叠语义 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  验收要点：
  - `_HeadingCollapseGlyph` 不再渲染 `_HeadingCollapseCountBadge`，折叠状态下只显示展开/收起方向图标。
  - 可见 UI 中不再出现隐藏块数量文本，例如折叠 3 个块时不显示 `3` 或 `99+` badge。
  - `HeadingCollapseState.hiddenBlockCount` 仍可用于 tooltip、语义说明或内部逻辑；折叠/展开逻辑和隐藏块投影不变。
  - 禁用态、只读态、键盘 Enter/Space 切换、焦点回收和 selection exclusion 行为保持不变。

- [x] P004: 优化块操作 popup 的 Chrome 风格视觉 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart,docs/design/menu_toolbar_minimal_spec.md -->
  验收要点：
  - `_BlockDragHandleButton` 的主菜单/更多菜单、`_ObjectMoreMenu`、`_FileBlockActionMenu` 继续复用 `_kPopupMenu*` 与 `_PopupMenuItemContent`，避免菜单项内新增零散硬编码样式。
  - Popup 容器在浅色/深色主题下均使用 `ColorScheme`：低饱和 surface、细 outline、弱阴影、透明 surface tint、紧凑圆角，整体接近浏览器/桌面应用 chrome。
  - 菜单项的 hover、pressed、selected、disabled、destructive 状态清晰且克制；禁用项保留位置，选中项只使用低透明高亮和主色图标/文字。
  - 菜单宽高、滚动、viewport clamp、route settings、dismissal、点击项后的 action 分发不改变。
  - 若调整 token 与设计规范不一致，同步更新 `docs/design/menu_toolbar_minimal_spec.md` 中 popup/menu token 说明。

- 左侧行级 chrome：折叠按钮、块操作按钮、拖拽/点击菜单、只读/可编辑态、键盘切换、selection exclusion。

- 回归：正文水平对齐、列表/引用/代码/表格/媒体块渲染、自定义 block renderer、outline 折叠投影、已有编辑行为。

通过标准：

1. 折叠按钮不显示任何隐藏数量 badge，可点击/键盘切换/tooltip 或语义仍正常。
2. 折叠按钮视觉中心与所在行高垂直居中，尺寸和外边距比当前实现更紧凑。
3. 折叠按钮不存在时，块操作按钮移动到折叠按钮 slot 并自动靠右贴近内容侧。
4. 块操作 popup 和编辑器其它 popup 在浅色/深色主题下视觉统一，符合紧凑、克制、Chrome 风格，不出现硬编码高饱和背景或低对比状态。
5. `flutter analyze`、定向测试和全量 `flutter test` 均通过；如更新 golden，更新后全量测试通过。
