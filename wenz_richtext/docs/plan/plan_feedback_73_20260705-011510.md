# 修复 Callout 块正文无法直接输入

## 需求概要

反馈 #73 指出 callout 内不能像代码块一样输入。项目中 CalloutBlockNode 的正文已经使用 PositionPath.blockText 和 _TextSelectionSurface，但部分通用插入/聚焦路径仍可能把 callout 当作对象块处理，且 EditorTextInputClient 通过 block.plainText 生成平台输入缓冲时会把 callout 标题混入正文偏移。计划修正 callout 正文的选择落点与输入缓冲，使插入后、点击后和 IME 输入都写入 content，并保留 title/icon/variant 等元数据。

## 任务拆解

- [x] P001: 修正 callout 插入与聚焦的默认选择落点 <!-- scope: lib/src/core/commands/block_commands.dart,lib/src/widgets/wenz_rich_text_editor.dart,lib/src/controller/wenz_rich_text_controller.dart -->
  - 验收要点：通过工具栏、上下文菜单或通用 insertBlocks 插入空 CalloutBlockNode 后，默认 selection 落在 PositionPath.blockText(calloutId) 的 offset 0，而不是 blockObject。
  - 验收要点：点击已有 callout 正文或空正文区域后，caret 能进入 callout.content，后续键盘输入写入正文。
  - 验收要点：Callout 的 title、icon、variant 控件仍可操作，不被正文点击区域或 selection exclusion 破坏。
- [x] P002: 修正 callout 正文的平台文本输入缓冲 <!-- scope: lib/src/input/editor_text_input_client.dart -->
  - 验收要点：当 selection 位于 CalloutBlockNode 正文时，TextInput buffer 只暴露 callout.content 的纯文本，不包含 title 或 effectiveTitle。
  - 验收要点：在 callout 正文中使用普通输入、删除、替换和 IME composing 时，偏移按正文长度映射，更新 CalloutBlockNode.content。
  - 验收要点：Paragraph、CodeBlockNode、table cell 的现有输入缓冲行为保持不变。
- [x] P003: 保持 callout 正文编辑命令与元数据边界一致 <!-- scope: lib/src/core/commands/text_commands.dart,lib/src/core/commands/selection_commands.dart,lib/src/core/commands/block_commands.dart -->
  - 验收要点：在 callout 正文内插入文本、删除选区、Backspace/Delete 不会清空或改写 title、icon、variant、attributes。
  - 验收要点：从相邻文本块移动到 callout 正文、以及跨 callout 正文边界的选择/删除，仍按正文边界处理。
  - 验收要点：空 callout 可作为合法可编辑正文块保留，不会被误判为不可编辑对象块。
- [x] P004: 补充 callout 可输入回归覆盖 <!-- scope: test/input/editor_text_input_client_test.dart,test/widgets/wenz_rich_text_editor_test.dart,test/core/text_commands_test.dart,test/core/block_commands_test.dart -->
  - 验收要点：覆盖 callout 正文的 TextInput buffer 不包含标题且 offset 与 content 对齐。
