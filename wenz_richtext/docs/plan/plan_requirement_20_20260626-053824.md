## 原始内容
todo和有序列表要支持同时出现

## 需求理解
- 当前列表模型统一使用 `TextBlockNode(type: BlockType.listItem)` 表示列表项，并通过 `BlockAttributes.listType` 区分无序列表、`ordered` 有序列表和 `task` todo 列表；`checked` 目前只在 `listType == 'task'` 时被 schema 保留。
- “todo 和有序列表同时出现”应覆盖两类场景：同一文档/相邻或嵌套列表中可混排 todo 列表与有序列表；同一个列表项也可同时具备有序编号和 todo 勾选状态，例如 Markdown `1. [ ] 待办项` / `1. [x] 已完成项`。
- 建议将 todo 勾选态建模为列表项的独立能力：`listType == 'ordered'` 负责编号，`checked != null` 负责 todo 状态；现有 `listType == 'task'` 继续作为兼容的无序 todo 表示，避免破坏历史 JSON、快捷输入和现有 API。
- 渲染层需要在有序 todo 项上同时展示有序编号和可交互 checkbox，编号连续性仍由同层级有序列表项决定；普通 todo 项继续展示 checkbox，普通有序项继续展示编号。
- 导入导出、Markdown 快捷输入、Enter 续行、切换 todo、复制/纯文本/HTML/JSON 等路径都需要保留两种属性，不应在互相转换时丢失编号或 checked 状态。

## 总体验收标准
- 所有任务 checkbox 完成，且每个任务的验收要点均有对应实现、测试或记录说明。
- 同一文档中普通有序列表、无序 todo 列表和有序 todo 列表可以相邻、连续或嵌套出现，渲染稳定且布局不溢出。
- 单个有序列表项可以同时具备编号和 todo checkbox，勾选/取消勾选不会改变其有序列表身份或编号连续性。
- JSON/schema、Markdown 导入导出、快捷输入、Enter 续行、切换 todo、设置 checked、缩进/反缩进和 block type 切换均不会意外丢失 `listType` 或 `checked`。
