# 反馈 #42 开发计划

**反馈内容**：表格组件，单元格设置对齐方式后渲染内容没有按照对齐方式进行对齐

**分析日期**：2026-07-04

---

## 问题分析

### 数据模型层（正确）
- `TableCellNode.alignment` 字段正确存储单元格对齐方式（`left`/`center`/`right`/`justify`/`null`）
- `TableModel.columnAlignments` 正确存储列级对齐
- `SetTableCellRangeAlignmentCommand` / `SetTableCellAlignmentCommand` 正确更新单元格对齐
- `WenzRichTextController.setAlignment()` 正确路由到表格单元格对齐命令
- `_copyCellWithAlignment()` 正确创建带有新对齐值的新 `TableCellNode`

### 渲染属性传递（正确）
- `_TableCellWidget.build()` 正确从 `cell.cell.alignment ?? table.columnAlignments[cell.columnIndex]` 计算 `textAlign`
- `_textAlign()` 函数正确映射 `'center'` → `TextAlign.center`，`'right'` → `TextAlign.right`，`'justify'` → `TextAlign.justify`
- `_TableCellSurface` → `_TextSelectionSurface` → `RichText` 属性链正确传递 `textAlign`
- 现有 widget 测试确认 `RichText.textAlign` 属性被正确设置

### 渲染布局层（问题所在）
- `_TableCellSurfaceState.build()` 使用 `Stack` 布局单元格内容
- `_TextSelectionSurface` 作为 Stack 的非定位子节点（non-positioned child），接收 `StackFit.loose` 约束
- `_TextSelectionSurfaceState.build()` 中 `textHitBoxMinWidth` 在表格单元格场景下（`hitTestKey != null`）被设为 `0.0`
- `RichText` 虽然 `textAlign` 属性被正确设置，但 `ConstrainedBox(minWidth: 0)` + `StackFit.loose` 约束组合可能导致文本组件无法占满单元格水平空间，使 `textAlign` 失去视觉效果

### 根本原因
表格单元格的文本渲染组件在 Stack 布局中，宽度约束为 loose（`minWidth=0, maxWidth=cellWidth-padding`），配合 `ConstrainedBox(minWidth: 0)` 时，`RichText` 可能不会充分扩展以让 `textAlign` 产生可见的对齐效果。需要通过以下任一方式修复：

1. 在 `_TextSelectionSurface` 中为表格单元格场景正确设置 `textHitBoxMinWidth`
2. 在 `_TableCellSurface` 中将文本表面包裹为 `Positioned.fill` 或使用 `Align(widthFactor: 1.0)` 确保水平填充
3. 在 Stack 中使用 `StackFit.expand` 或 `Positioned.fill` 包裹文本表面
