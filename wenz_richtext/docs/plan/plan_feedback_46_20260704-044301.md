# 开发计划：修复手动滚动时跳回光标位置的死循环问题

**反馈编号**：46  
**反馈日期**：2026-07-04  
**问题描述**：往下滚动时，有时会跳回光标位置，导致死循环，无法持续往下滚动。

---

## 问题分析

### 根因定位

该问题发生在虚拟化块列表的测量回调与光标自动可见性逻辑之间的反馈循环中：

1. 用户手动向下滚动（滚轮 / 触控板 / 拖拽滚动条）→ `_scrollController.offset` 增大
2. 新的块进入视口，`_MeasuredVirtualBlockList` 对它们进行测量布局
3. `_handleExtentChanged` 触发 → 调用 `widget.onExtentUpdated` → 即 `_scrollCaretIntoViewIfNeeded`（`wenz_rich_text_editor.dart:2117,5032`）
4. `_scrollCaretIntoViewIfNeeded` 在下一帧调度 `_scrollCaretIntoView()`（`wenz_rich_text_editor.dart:5058`）
5. `_scrollCaretIntoView` 发现光标已移出视口（因为用户向下滚过了光标位置），调用 `_jumpToScrollOffset` 将滚动偏移跳回光标位置
6. 滚动跳跃可能导致更多块需要重新测量 → 回到步骤 2 → **形成一个反馈死循环**

### 核心缺陷

`_scrollCaretIntoView` 及其间接调用者 `_scrollCaretIntoViewIfNeeded` **无法区分**"用户主动滚离光标"（不应自动滚回）与"光标因编辑/选择变更而移出视口"（应自动滚回）。当前所有来源的滚动变更或块范围更新都会无条件尝试把光标拉回视口。

### 次要触发路径

除 `onExtentUpdated` 外，以下路径也可能在用户滚动期间被触发从而加剧问题：

- `_handleControllerChanged`（`wenz_rich_text_editor.dart:1763`）：控制器通知变更时，若光标 key 变化会调用 `_scrollCaretIntoView`
- `_handleOutlineControllerChanged`（`wenz_rich_text_editor.dart:1695`）：大纲控制器变更时无条件调度 `_scrollCaretIntoView`

## 任务拆解

- [x] P001: 添加用户滚动检测机制 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  - 在 `_WenzRichTextEditorState` 中新增字段：
    - `DateTime? _lastUserScrollTime`：记录最近一次用户主动滚动的时间戳
    - `static const Duration _kUserScrollCooldown`：用户滚动冷却期（建议 300 ms），在此期间抑制光标自动回到视口的逻辑
  - 在 `build` 方法的 `_MeasuredVirtualBlockList` 外层（或与 `SelectionGestureOverlay` 同级位置）包裹 `NotificationListener<ScrollUpdateNotification>`，在回调中记录 `_lastUserScrollTime = DateTime.now()`
  - **注意**：`ScrollUpdateNotification` 仅由用户手势（拖拽、滚轮、触控板）触发，不会在 `jumpTo` / `animateTo` 等程序化滚动时触发，因此天然区分用户滚动与代码滚动
  - 验收要点：
    - 用户手指拖动滚动、鼠标滚轮滚动、触控板滚动时 `_lastUserScrollTime` 被正确更新
    - `jumpTo` 调用不触发 `ScrollUpdateNotification`，`_lastUserScrollTime` 保持原值

- [x] P002: 改造 `_scrollCaretIntoViewIfNeeded` 增加用户滚动冷却检查 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  - 在 `_scrollCaretIntoViewIfNeeded` 方法开头增加逻辑：
    - 若 `_lastUserScrollTime != null` 且 `DateTime.now().difference(_lastUserScrollTime!) < _kUserScrollCooldown`，则直接 return，不调度 `_scrollCaretIntoView`
  - 同时检查光标 key（`_CaretKey`）是否真的发生了变化；若与 `_lastScrollCheckedCaret` 相同则跳过。此优化避免在用户滚动期间因块范围更新（触发 `onExtentUpdated`）而重复调度
  - 验收要点：
    - 用户手动滚动期间（冷却期内），`_scrollCaretIntoView` 不被调用
    - 冷却期结束后若有新光标位置变更，`_scrollCaretIntoView` 正常恢复工作
    - 非用户滚动场景（编辑导致光标移出视口），该检查不阻止正常的光标可见性滚动

- [x] P003: 优化 `_handleExtentChanged` 的光标可见性触发条件 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  - 在 `_handleExtentChanged`（`_MeasuredVirtualBlockListState` 内）中，仅当范围变化实际影响光标所在块的布局时才触发 `onExtentUpdated`
  - 实现方式：
    - 检查 `_MeasuredVirtualBlockListState` 中当前光标所在 blockId 是否在最近的 contain / visible 范围内
    - 若光标不在本次更新的 blockId 范围，且用户未在冷却期内，才调用 `onExtentUpdated`
    - 或者更简洁的方案：将 `onExtentUpdated` 的触发延迟到非用户滚动期（即让 P002 的冷却检查处理大部分 case，此任务作为防御性补充）
  - 验收要点：
    - 远距离的手动滚动（光标离视口很远时）不会因为视口内块测量触发光标滚动回调
    - 光标所在块的编辑和测量仍然能正常触发可见性检查

- [x] P004: 防止 `_handleControllerChanged` 和 `_handleOutlineControllerChanged` 在用户滚动期间触发光标回跳 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  - `_handleControllerChanged` 中（约 `wenz_rich_text_editor.dart:1763`）在调度 `_scrollCaretIntoView` 前增加用户滚动冷却检查
    - 若在冷却期内且光标 key 未变（`caretKey == _lastScrollCheckedCaret`），跳过 `_scrollCaretIntoView` 调用
  - `_handleOutlineControllerChanged` 中（约 `wenz_rich_text_editor.dart:1695`）同样增加冷却检查
  - 验收要点：
    - 用户在滚动期间触发的任何控制器通知不会导致滚动跳回光标
    - 非滚动场景（如查找替换跳转、大纲点击跳转）的光标可见性滚动不受影响

- [x] P005: 完整验收 <!-- scope: validation -->
  - 编译验证：`flutter analyze` 零错误
  - 功能验收（手动测试）：
    1. 在长文档中（超过 2 屏），将光标放在文档开头（第 1 行），然后用滚轮/触控板向下滚动到文档末尾 —— 滚动应流畅，不应跳回光标位置
    2. 同样场景，用鼠标拖拽滚动条快速向下滚动 —— 不应跳回
    3. 在长文档中，将光标放在中间位置，向上滚动到文档开头 —— 不应跳回
    4. 编辑操作导致光标移出视口（如在文档末尾插入内容使光标在视口下方）—— 编辑器的自动滚动应正常工作，将光标带回视口
    5. 使用查找替换功能跳转到某个匹配项 —— 应正常自动滚动到匹配位置
    6. 大纲面板点击标题跳转 —— 应正常自动滚动
  - 验收标准确认：
    - 用户手动滚动永远不会被程序化光标可见性逻辑打断
    - 编辑和导航导致的光标移出视口场景仍能正确自动滚动

## 总体验收标准

1. **编译通过**：`flutter analyze` 零错误、零警告（warning 仅允许已有的）
2. **手动滚动不跳回**：在任意长度的富文本文档中，用户通过任何输入方式（滚轮、触控板、触摸拖拽、滚动条）手动滚动时，滚动偏移永远不会被程序化为光标位置覆盖
3. **编辑自动滚动不退化**：以下场景的光标自动可见性滚动仍然正常工作：
   - 键盘导航（上下左右、PageUp/PageDown、Home/End）使光标移出视口
   - 在视口底部编辑导致光标超出视口（新行自动滚动）
   - 查找替换跳转
   - 大纲/目录点击跳转
4. **无回归**：现有自动化测试全部通过（`flutter test`）
