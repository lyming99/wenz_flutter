# 开发计划：表格Cell居中对齐/居右对齐后文字选择与选择器修复

**反馈编号**：47  
**反馈日期**：2026-07-04  
**问题描述**：
1. 表格 cell 居中、居右后，文字选择存在问题（选择高亮位置或范围不正确）
2. 表格 cell 选择器存在问题：当前使用基于行列索引的矩形包围盒（`TableCellRange.containsCell`）判断哪些 cell 应高亮，应该根据 start 光标和 end 光标的像素坐标计算 `min(left), min(top), max(right), max(bottom)` 作为约束矩形，仅对与该矩形相交的 cell 渲染选中高亮，避免不在可视范围内的 cell 被错误选中

---

## 问题分析

### 问题1：居中对齐/居右对齐 cell 内文字选择异常

**根因**：`_selectionRangeForPath`（`wenz_rich_text_editor.dart:14854`）在为表格 cell 计算局部选择范围时，使用 `PositionPath.compare()` 进行路径排序比较。该比较基于 path 的 `_kind.rank` + segments 的字典序比较，在语义上是正确的（同表内按 row/column 排序）。但 `_SelectionHighlightPainter.paint()` 依赖 `_InlineOffsetMapper.renderOffsetForLogicalOffset()` 将逻辑偏移映射到渲染偏移，然后调用 `TextPainter.getBoxesForSelection(renderStart, renderEnd)` 获取选择框。

当 cell 使用 `TextAlign.center` / `TextAlign.right` 时，`TextPainter` 在布局阶段已将文本位移到居中/居右位置。`getBoxesForSelection` 返回的 boxes 坐标是 text-painter-local 的（已包含对齐位移），所以绘制本应正确。但问题可能出在 `_TableCellSurface` 内部的 `_TextSelectionSurface` 被包裹在 `Padding` + `Stack` 中，而 `_hitLocalToTextLocal` 的坐标变换（line 10850）在居中/居右场景下可能产生偏移，导致：
- 点击/拖拽落点映射到错误的逻辑偏移
- 选择高亮渲染时使用的逻辑范围与实际视觉位置不匹配

**影响范围**：`_TextSelectionSurface._hitLocalToTextLocal`、`_SelectionHighlightPainter.paint`、`_TableCellSurfaceState.build` 中 cell 选择态判断。

### 问题2：Cell 选择器使用索引包围盒而非视觉坐标

**根因**：`_shouldHighlightTableCell`（`wenz_rich_text_editor.dart:10156`）当前的核心逻辑：

```dart
// 表内拖拽：使用 TableCellRange.containsCell(row, column)
final range = selection.tableCellRange;
if (range != null) {
  return range.containsCell(rowIndex, columnIndex);
}
// 跨块选择部分覆盖：使用行优先索引比较
return rowIndex > sr || (rowIndex == sr && columnIndex > sc);
```

`TableCellRange.containsCell` 是纯二维索引矩形判断（`row >= startRow && row <= endRow && column >= startColumn && column <= endColumn`）。这存在以下缺陷：

1. **对角选择误包含**：在非规则网格（含合并 cell）中，从 cell A 拖拽到 cell B 时，索引包围盒会包含所有中间 cell，即使某些 cell 不在用户直观的拖拽路径上。例如合并 cell 跨越的行列可能导致视觉空白区域对应的实际 cell 被错误高亮。

2. **跨块选择不完全覆盖**：行优先比较（`rowIndex > sr || ...`）在命中时可能遗漏或冗余包含部分 cell，尤其是在存在 rowSpan/columnSpan 的合并 cell 场景下，视觉位置与索引位置不完全对应。

**修复方向**：使用 `_TableGridMetrics` 中已有的 cell 布局信息（`left`, `top`, `width`, `height`），从 selection 的 start/end 光标所在 cell 计算视觉约束矩形，然后对每个 cell 做 `Rect.overlaps` 相交判断。

## 任务拆解

- [x] P001: 新增视觉坐标约束矩形计算方法 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  - 在 `_TableGridMetrics` 或表渲染函数中新增辅助函数 `_selectionRectForTableCells`：
    - 输入：`TableModel`、`_TableGridMetrics`、`DocumentSelection`
    - 从 `selection.start` 和 `selection.end` 分别获取其所在的 cell 在 grid metrics 中的 `_TableGridCell`
    - 计算两个 cell 的视觉矩形：`Rect.fromLTWH(cell.left, cell.top, cell.width, cell.height)`
    - 返回合并矩形：`startRect.expandToInclude(endRect)` — 即 `min(left), min(top), max(right), max(bottom)`
  - 边界处理：
    - 当 start/end 不在当前表格内（跨块选择），仅对端点所在表格计算单侧约束（以表格边界为 clamps）
    - 当 selection 为 collapsed 或无 `tableCellRange` 时，返回 `null`
  - 验收要点：
    - 水平方向从 cell A（col=0）到 cell B（col=2）：合并矩形 left 为 A 的 left，right 为 B 的 right
    - 垂直方向从 cell A（row=0）到 cell B（row=2）：合并矩形 top 为 A 的 top，bottom 为 B 的 bottom
    - 合并 cell（rowSpan=2, colSpan=2）：其视觉矩形正确覆盖跨行列区域
    - 跨表选择时返回 `null`（不在此表格范围内）

- [x] P002: 重构 `_shouldHighlightTableCell` 使用视觉矩形相交判断 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  - 修改 `_shouldHighlightTableCell` 签名，新增 `_TableGridMetrics? gridMetrics` 参数
  - 核心逻辑改造：
    - 若 `gridMetrics != null` 且存在有效 `TableCellRange`：
      1. 调用 P001 的 `_selectionRectForTableCells` 计算视觉约束矩形 `selRect`
      2. 从 `gridMetrics.cells` 查找当前 `(rowIndex, columnIndex)` 对应的 `_TableGridCell`
      3. 构造 `cellRect = Rect.fromLTWH(cell.left, cell.top, cell.width, cell.height)`
      4. 返回 `cellRect.overlaps(selRect)`（即 Rect 有交集）
    - 若 `gridMetrics == null`（向后兼容，非表格场景）或为跨块选择（`tableCellRange == null`），保留现有逻辑不变
  - 调用点更新：
    - 表渲染处（line 9314-9320）传入 `metrics`（即 `_TableGridMetrics` 实例）
  - 验收要点：
    - 标准矩形选择（row 0-2, col 1-3）：所有行列索引在范围内的 cell 均正确高亮（与原有行为一致）
    - 含合并 cell 的对角选择：仅与视觉约束矩形相交的 cell 被高亮，不相关的 cell 不被误选中
    - 跨块选择场景（表格外拖入/拖出）：视觉矩形边界正确的 cell 被高亮
    - 单 cell 选择：`isSingleCell` 仍返回 `false`（无整 cell 高亮），仅依赖 `_selectionRangeForPath` 的文本级高亮

- [x] P003: 修复居中/居右 cell 内文字选择的坐标映射与高亮渲染 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  - **3a. 审查并修复 `_hitLocalToTextLocal` 的时钟对齐**：
    - 在居中/居右 cell 中，`RichText` widget 的 render box 填充整个 cell 内容区宽度（`textHitBoxMinWidth = maxWidth`），但 `TextPainter` 将文本绘制在居中/居右位置
    - `_hitLocalToTextLocal` 使用 `cellOrigin - textOrigin` 做坐标变换，该差值在居中/居右场景下应接近 `padding` 值（两者共享相同的 `Padding` 父级）
    - 验证该变换在不同对齐模式下的正确性；如有偏差导致 hit 落点偏移，修正变换计算
  - **3b. 确保 `_SelectionHighlightPainter` 范围计算正确**：
    - `_SelectionHighlightPainter.paint` 使用 `offsetMapper.renderOffsetForLogicalOffset` 映射逻辑→渲染偏移
    - 确认对于纯文本 cell（无 inline embed），`_InlineOffsetMapper` 为 identity 映射，`renderStart/renderEnd == logicalStart/logicalEnd`
    - 确认 `TextPainter.getBoxesForSelection` 在 `TextAlign.center/right` 下返回的 boxes 坐标是正确的（已在 painter local space 中包含对齐位移）
  - **3c. 确认 `_TableCellSurface` 的选择态一致性**：
    - `selected` 标志（line 10341）由 `highlightWholeCell || _selectionRangeForPath(...) != null` 决定
    - 当 `highlightWholeCell` 为 true 时，整 cell 蓝色背景覆盖（`Positioned.fill` 的 `DecoratedBox`）
    - 当 `_selectionRangeForPath` 返回非 null 时，`_TextSelectionSurface` 内 `_SelectionHighlightPainter` 绘制文本级高亮
    - 确保居中/居右 cell 中两条路径的坐标系统一致，不会出现高亮错位
  - 验收要点：
    - 居中 cell 内拖拽选择文字：高亮框与文字位置精确对齐，无偏移
    - 居右 cell 内拖拽选择文字：同上
    - 居中 cell 内点击放置光标：光标显示在正确视觉位置
    - 居右 cell 内双击选中单词：选中高亮正确覆盖单词区域
    - 混合对齐（同一表中部分 cell 左对齐、部分居中、部分居右）跨 cell 选择：各 cell 内高亮正确
