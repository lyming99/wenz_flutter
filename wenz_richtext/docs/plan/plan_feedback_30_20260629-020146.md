# 反馈 #30 开发计划：公式弹窗输入框与编辑器键盘焦点冲突

- 反馈编号：#30
- 生成时间：2026-06-29
- 反馈内容：编辑器本身键盘，会和公式 popup 输入框键盘抢焦点，无法在 popup 里面使用键盘方向键

## 背景与根因分析

公式编辑弹窗由 `_WenzRichTextEditorState` 在编辑器 `Stack` 内直接构建（不是独立 Overlay）：

- `_buildFormulaEditorOverlay()`（`lib/src/widgets/wenz_rich_text_editor.dart:1940`）返回一个 `Positioned`，包裹
  `_FormulaEditPopup`（`lib/src/widgets/wenz_rich_text_editor.dart:773`）。
- `_FormulaEditPopup` 内部的输入控件是 `TextField`，`focusNode: _formulaEditFocusNode`、
  `controller: _formulaEditController`（`wenz_rich_text_editor.dart:828-841`）。
- 该 `Positioned` 作为 `editorStack.children` 的一员（`wenz_rich_text_editor.dart:1913`），而 `editorStack`
  被包裹在 `_buildEditorShell`（`wenz_rich_text_editor.dart:2047`）里。

`_buildEditorShell` 的最外层是一个 `Focus`：

- `Focus(focusNode: focusNode, autofocus: widget.autofocus, onKeyEvent: _handleKeyEvent, ...)`
  （`wenz_rich_text_editor.dart:2062-2065`）。

因此弹窗里的 `TextField`（`_formulaEditFocusNode`）在 **焦点树** 上是编辑器 `focusNode` 的后代。键盘事件按
Flutter 焦点链「从 primary focus 向祖先冒泡」的规则派发：当弹窗输入框持有焦点、用户按下方向键时，事件会从
`_formulaEditFocusNode` 冒泡到祖先编辑器 `Focus`，进入 `_handleKeyEvent`。

`_handleKeyEvent`（`lib/src/widgets/wenz_rich_text_editor.dart:3338`）的处理顺序为：

1. `_handleSlashMenuKeyEvent`（斜杠菜单方向键/回车/Esc）——仅当斜杠菜单开启时生效，与公式弹窗无关。
2. `_handleCodeBlockTabKeyEvent`（代码块 Tab 缩进）——仅在代码块内生效。
3. `_shortcutManager.resolve(...)`（`lib/src/input/shortcut_manager.dart:335-356`）将方向键解析为
   编辑器光标移动意图：`arrowLeft → moveCaretBackward`、`arrowRight → moveCaretForward`、
   `arrowUp → moveCaretUp`、`arrowDown → moveCaretDown`，`disposition == handled`。
4. 命中后调用 `_performShortcut` 移动 **编辑器文档光标**，并 `return KeyEventResult.handled`。

结果：方向键被编辑器 `_handleKeyEvent` 拦截并消费（移动了编辑器正文光标、返回 `handled`），无法到达弹窗
`TextField`，表现为「在 popup 里用键盘方向键没有反应 / 焦点被编辑器抢走」。这与反馈描述的「编辑器键盘和公式
popup 输入框抢焦点，无法在 popup 里使用键盘方向键」完全吻合。

补充确认：

- 弹窗打开入口 `_openFormulaEditor`（`wenz_rich_text_editor.dart:1722`）已在 `setState` 后的 post-frame 回调
  里调用 `_formulaEditFocusNode.requestFocus()`（`wenz_rich_text_editor.dart:1734-1738`），初始获焦逻辑存在，
  但缺乏对「事件冒泡被祖先 Focus 拦截」这一路径的防御。
- 编辑器 IME 客户端 `_inputClient` 在 `_handleFocusChanged`（`wenz_rich_text_editor.dart:1594-1610`）按
  `focusNode.hasFocus` attach/detach，焦点切到弹窗时会 detach，本身不抢键盘；核心问题仍是方向键事件被
  `_handleKeyEvent` 拦截。

结论：需要在编辑器键盘处理入口处，识别「公式弹窗输入框持有焦点」的状态并放行事件；同时确保弹窗 `TextField`
能可靠获焦，避免编辑器侧任何路径回收焦点。

## 修复方案

在 `_WenzRichTextEditorState._handleKeyEvent` 顶部增加「公式弹窗输入态」守卫：当公式弹窗处于打开态且其输入框
`_formulaEditFocusNode` 持有焦点（或更宽松地：弹窗 `_formulaEditTarget != null` 时）时，立即
`return KeyEventResult.ignored`，让方向键等导航/编辑键由 `TextField` 自行处理，编辑器不再消费、不再移动
正文光标。该守卫必须放在 `_handleSlashMenuKeyEvent` / `_handleCodeBlockTabKeyEvent` / `_shortcutManager.resolve`
之前。

- 推荐精确判据：`if (_formulaEditFocusNode.hasFocus) return KeyEventResult.ignored;`
  （输入框真正持焦时放行，最贴近「弹窗输入态」语义）。
- 可选加强：`if (_formulaEditTarget != null) return KeyEventResult.ignored;`
  （弹窗打开即为模态——已有 `Positioned.fill GestureDetector` + `TapRegion onTapOutside` 关闭弹窗——
  打开期间编辑器整体作为事件直通更稳妥）。两种取一即可，硬性要求是 **弹窗输入框持焦时方向键不再被编辑器拦截**。
- 同步确保弹窗 `TextField` 可靠获焦并保持：`_openFormulaEditor` 的 post-frame `requestFocus()` 已存在，建议给
  `_FormulaEditPopup` 的 `TextField` 增补 `autofocus: true`（`wenz_rich_text_editor.dart:828-841`）作为兜底，
  防止 post-frame 与重建时序竞争导致焦点未落到输入框；并确认编辑器侧不存在在弹窗打开期间 `requestFocus()` 回收
  焦点的路径。
