# 需求 #62 开发计划：链接支持 Ctrl/Cmd+点击打开与 hover「编辑|打开」浮层

- 需求编号：#62
- 创建日期：2026-06-28
- 状态：待评审

## 需求概述

为正文中的链接（`TextAttributes.url` 非空的内联文本）补齐交互能力：

1. **Ctrl（macOS 下 Cmd）+ 点击链接 → 打开**：按下平台修饰键点击链接时打开其 URL，且不应移动光标/选区（普通点击仍按现状落位光标，保证链接文本可编辑）。
2. **鼠标 hover 链接 → 在链接上方显示浮层 popup**：浮层含「编辑」「打开」两个操作。
   - 「编辑」：选中该链接所在文本区间，弹出已有的链接编辑对话框（`showWenzLinkEditDialog`），应用 `setLink`（支持清空）。
   - 「打开」：打开该链接 URL（通过 `onOpenLink` 回调，由宿主决定具体打开方式）。
3. 浮层定位在链接**上方**；指针离开链接（及浮层）后消失，带短暂隐藏延迟以便指针移入浮层。
4. 只读模式下隐藏「编辑」，仅保留「打开」。

> 范围限定为**鼠标/触控笔 hover + 桌面修饰键点击**的桌面端交互；触摸设备无 hover，本需求不为其提供 hover 浮层（触摸点击仍按现状落位光标）。

## 现状分析（勘察结论）

- **链接渲染**：链接样式集中在 `lib/src/widgets/wenz_rich_text_editor.dart` 的 `_resolveInlineAttributes`（约 12580–12635 行）：当 `attrs.url != null` 时叠加 `TextDecoration.underline`、前景/下划线用 `_inlineLinkColor`（`_kInlineLinkColor = 0xFF1976D2`，定义于第 93 行，取色于第 11750 行）。即链接已**有可识别的视觉样式**，但**完全没有可交互性**（无 recognizer、无点击/hook）。
- **链接编辑能力已存在，但分散**：
  - 对话框：`lib/src/widgets/link_edit_dialog.dart` 的 `WenzLinkEditDialog` / `showWenzLinkEditDialog(context, initialUrl, canRemove)`，返回 `String?`（`null`=取消，`''`=移除，否则为新 URL）。
  - 写入：`WenzRichTextController.setLink(url)`（`lib/src/controller/wenz_rich_text_controller.dart:1468`）→ `SetLinkCommand`，作用于**当前选区**。
  - 当前编辑流程**由宿主工具栏驱动**，不在库内编辑器里：`example/lib/main.dart:1043-1053` 的 `_showLinkDialog` 先读 `toolbar.linkUrl`、弹窗、再 `toolbar.setLink(...)`。**库编辑器自身从不打开该对话框**。
- **位置→内联属性解析已有可复用模式**：
  - 编辑器内 `_inlineNodesForPosition(DocumentPosition)`（约 2198 行）可取到某 block/path 的内联节点列表；`_mentionEmbedAtPosition`（2178 行）与 `_dispatchMentionTapForSelection`（2154 行）已演示「按位置累加 offset 定位节点」的模式。
  - `lib/src/core/commands/revision_commands.dart:494` 的私有 `_attributesAtOffset(List<InlineNode>, int offset)` 即「取某 offset 处 `TextAttributes`」的现成实现，可作为链接解析的蓝本。
- **几何/手势层**：
  - `lib/src/widgets/block_geometry_registry.dart:308` `positionFromGlobalOffset(Offset)` 已能由全局坐标解析 `DocumentPosition`；`caretRectForPosition`（482 行）/`wordRangeAt`（464 行）可拿到坐标范围。为把浮层锚定到「链接文本上方」，需要由链接区间 `[start,end)` 计算一个全局 `Rect`（可用首尾 caret rect 合并，或取区间起点 caret rect 的顶边）。
  - `lib/src/widgets/selection_gesture_overlay.dart` 是文档级手势/指针/hover 的唯一拥有者：`MouseRegion(onHover: _onPointerHover)`（117/134 行）、`Listener` 的 `_onPointerDown`（185）/`_onPointerUp`（255）。当前 `_onPointerHover` 只跟踪是否在滚动条 gutter 上以切换鼠标光标（146 行 `_resolvedCursor`），**完全不感知链接**；pointer 事件未读取任何修饰键状态。
- **浮层锚定范式可复用**：`lib/src/widgets/table_floating_toolbar_overlay.dart` 已用 `LayerLink` + `anchorRect` + `visibleTop` 把浮动工具栏锚定到选区上方/下方，并在 `wenz_rich_text_editor.dart:7392-7417` 通过 `TableFloatingToolbarOverlayAnchor` 接入；`slash_menu_overlay.dart` 的圆角/阴影/边框 token（`_kSlashMenuSurfaceRadius` 等）可复用以保持视觉一致。
- **打开 URL 无现成依赖**：`pubspec.yaml` 仅有 `flutter`/`flutter_math_fork`/`highlight`/`html`，**未引入 `url_launcher`**；库内也没有「打开外链」的任何实现或回调。库的设计一贯用**回调**而非硬平台依赖（见 `onMentionTap` `WenzMentionTapCallback` 于第 1038 行、`mediaResolver`、`inlineEmbedRenderer`）。
- **既有测试覆盖**：`test/widgets/link_edit_dialog_test.dart` 仅覆盖对话框本身；`test/widgets/wenz_rich_text_editor_test.dart` 含大量结构性/交互用例，但无「链接 hover 浮层 / Ctrl+点击打开」相关用例。

## 方案与关键决策

1. **打开链接走回调，不引入平台插件**：库**不**直接依赖 `url_launcher`。新增 `WenzLinkInteractionCallback`（形如 `void Function(String url, DocumentPosition position)`）与 `WenzRichTextEditor.onOpenLink` 字段。Ctrl/Cmd+点击与浮层「打开」均调用该回调；具体打开方式（浏览器/应用内/白名单）由宿主决定。示例应用（`example`）再引入 `url_launcher` 接入，演示端到端打开。这与 `onMentionTap` 的既有哲学一致，且便于在 widget 测试中断言回调触发。
2. **「编辑」由库内编辑器自洽完成**：浮层「编辑」→ 先 `controller.setSelection(...)` 选中链接区间 → 调用库内已有的 `showWenzLinkEditDialog(initialUrl, canRemove: true)` → `controller.setLink(result)`。无需宿主额外接线即可工作（`setLink`/`SetLinkCommand`/对话框均为库内 API）。
3. **位置→链接解析下沉到编辑器 state**：新增 `_linkInfoAtPosition(DocumentPosition) → ({String url, TextRange range, Rect globalRect})?`，复用 `_inlineNodesForPosition` + `_attributesAtOffset` 模式遍历内联节点，定位包含 offset 且 `url != null` 的连续 run（合并相邻同 url run），并用几何层取其全局 `Rect`。该 resolver 是 Ctrl+点击与 hover 浮层的共同基础。
4. **手势层增强（`SelectionGestureOverlay`）**：
   - 新增可选回调 `linkProbe: Offset(global) → ({url, range, globalRect})?`（由编辑器用 resolver + registry 实现）。
   - **hover 链路**：`_onPointerHover` 解析到链接时上报「hover 中的链接信息」，移出链接（含移入浮层）经短延迟后清空；编辑器据此显示/隐藏浮层并锚定位置。浮层与指针之间的移入容忍由「隐藏延迟 + 浮层自身 hover 保持」实现。
   - **Ctrl/Cmd+点击**：`_onPointerDown`/`_onPointerUp` 通过 `HardwareKeyboard.instance.isControlPressed`（全平台）或 `isMetaPressed`（macOS）判定修饰键；若点击命中链接且带修饰键 → 触发「打开」回调并**抑制**光标落位/选区（提前 `return`，不进入既有 tap/选区逻辑）。普通点击命中链接仍按现状落位光标。
5. **浮层为新独立 widget**：新增 `lib/src/widgets/link_hover_overlay.dart`（`WenzLinkHoverOverlay`），视觉复用 slash menu 的圆角/阴影/边框 token，内容为 `[编辑] [打开]`（可附带 URL 摘要）；用 `LayerLink`/`Overlay` 锚定在链接 `Rect` 上方（`targetAnchor: bottomCenter` 对链接 `topCenter`，加 gap）。锚定写法对齐 `TableFloatingToolbarOverlay`。只读模式下不渲染「编辑」。
6. **范围边界**：仅新增链接 hover 浮层 + Ctrl/Cmd+点击打开 + `onOpenLink` 回调 + 示例接入；不改链接渲染样式、不改动普通点击/拖拽/多击选区行为、不触碰其它浮层（slash/table/comment）、不引入新的全局依赖到库 `pubspec.yaml`。
7. **仅桌面端 hover**：hover 浮层与 Ctrl+点击以鼠标/触控笔为前提；触摸点击不显示浮层（落位光标行为不变）。
