# 反馈 #37 开发计划：表格 cell 对齐与 popup 分割线弱化

- 反馈编号：37
- 生成时间：2026-07-03 21:15:15
- 反馈内容：表格 cell 内容无法修改对齐方式，无法居中，无法右对齐；各种 popup 分割线要淡一些。

## 背景与现状

当前项目是 Flutter 富文本编辑器包。表格模型已同时存在列级 `TableModel.columnAlignments` 和单元格级 `TableCellNode.alignment`，渲染层在 `lib/src/widgets/wenz_rich_text_editor.dart` 中通过 `cell.alignment ?? table.columnAlignments[column]` 决定单元格文本对齐。控制器也已有 `setTableCellAlignment`，核心命令 `SetTableCellAlignmentCommand` 能写入 cell 级 alignment。

反馈仍然成立的高概率原因集中在交互与属性保真层：表格浮动工具栏菜单中的对齐文案仍表现为“列对齐”概念，容易误导用户；同时 `SetTableCellHeaderCommand`、`SetTableCellBackgroundCommand`、合并/拆分单元格等路径重建 `TableCellNode` 时没有完整保留 `alignment`，会导致已经设置的居中/右对齐在后续表格操作中丢失。现有 widget 测试已覆盖“toolbar 对齐写入 cell 而不是 column”的基本路径，但缺少“对齐后执行表头、背景、合并、拆分仍保留 alignment”的回归场景。

popup 视觉方面，`wenz_rich_text_editor.dart` 中的表格更多菜单、对象块更多菜单、文件块菜单使用多处 `PopupMenuDivider(height: _kPopupMenuDividerHeight)`；浮动工具栏内部竖向分割线使用 `_kMinimalFloatingToolbarDividerAlpha = 120`。这些分割线与当前中性菜单 surface 相比偏重，应抽出更淡的分割线颜色/token，并统一应用到编辑器内所有 popup 菜单分组线。

## 目标

- 表格 cell 对齐通过 UI 可稳定修改，单选 cell 可居中/右对齐，多选 cell 范围可批量修改；不会误改列级 `columnAlignments`。
- 单元格对齐设置后，切换表头、设置/清除背景、合并/拆分等表格操作不会意外清空 `TableCellNode.alignment`。
- 表格浮动工具栏更多菜单的文案、tooltip 和行为统一表达“单元格对齐”，避免“列对齐”误导。
- 编辑器内各类 popup 菜单分割线更淡，light/dark theme 下仍可区分菜单分组但不抢视觉焦点。
- 通过定向 core/widget 测试覆盖对齐保真和 popup 分割线视觉 token，最终再执行完整验收。
