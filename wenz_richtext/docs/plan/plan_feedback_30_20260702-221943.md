# 反馈 #30 开发计划：提及行内组件搜索与信息展示

- 反馈编号：30
- 生成时间：2026-07-02 22:19:43
- 反馈内容：提及行内组件无法点击显示被提及的用户，模拟窗口显示，后续应该通过外部自定义接口接入提及搜索，以及提及信息显示事件；提及指的是行内元素，“@xxx”。

## 背景与现状

项目现有模型已经把提及定义为行内元素：`InlineEmbed(embedType: 'mention', data: {'id': ..., 'label': ...})`。`WenzRichTextController.insertMention` 可插入固定 mention，默认渲染会显示为 `@label` / `@mention`，`WenzRichTextEditor.onMentionTap` 与 `WenzMentionTapDetails` 已能承载点击详情事件，widget 测试也已有 mention 命中边界与点击回调覆盖。

当前缺口主要在完整业务链路：example 工具栏仍固定插入 `u-demo/Ada`，没有通过外部搜索接口选择用户；编辑器没有面向 `@xxx` 输入的 mention 搜索浮层；示例也没有把点击 mention 后展示被提及用户信息的模拟窗口串起来。计划按最小侵入方案推进：保留现有 `InlineEmbed` 与 `onMentionTap` 事件，新增可选搜索接口和示例 mock，实现从输入 `@` 到搜索、选择、插入、点击查看详情的闭环。

## 目标

- 输入 `@` 或 `@关键词` 时，可通过外部自定义接口搜索候选用户。
- 选择候选用户后，把查询文本替换为一个 mention `InlineEmbed`，并保留 `id`、`label` 及业务扩展数据。
- 点击文档中的 `@xxx` mention 时，向外部抛出稳定的提及信息展示事件；example 用模拟窗口展示用户信息。
- 不破坏现有 mention 渲染、选择、复制、只读点击和自定义 inline renderer 行为。

  验收要点：
  - 编辑器在普通文本、callout 文本和表格单元格文本内识别当前光标前的 `@` 查询片段；不在公式、emoji、已有 mention 等原子 inline embed 内触发。

  - 支持键盘 ArrowUp/ArrowDown/Enter/Escape 与鼠标点击选择；选择后用 mention embed 替换当前 `@xxx` 文本。
  - 浮层打开时不抢占公式弹窗、斜杠菜单、链接 hover 等既有 overlay 的核心交互；关闭后编辑器光标与 IME 状态恢复正常。
  - `readOnly` 或无搜索接口时不触发搜索浮层，现有手动插入与点击事件不受影响。
