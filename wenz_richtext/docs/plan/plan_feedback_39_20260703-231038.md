# 反馈 #39 开发计划：单元格居中对齐工具栏设置无效

- 反馈编号：39
- 生成时间：2026-07-03 23:10:38
- 反馈内容：单元格无法居中对齐，工具栏设置后无效

## 背景与现状

项目是 Flutter 富文本编辑器包。当前表格模型已经具备两层对齐能力：`TableModel.columnAlignments` 表示列级对齐，`TableCellNode.alignment` 表示单元格级对齐；渲染层在 `lib/src/widgets/wenz_rich_text_editor.dart` 中通过 `cell.alignment ?? table.columnAlignments[columnIndex]` 解析 `TextAlign`，因此模型和渲染侧具备居中显示基础。

现有表格浮动工具栏已经有“单元格居中对齐”菜单项，并通过 `_setTableCellAlignment` 调用 `WenzRichTextController.setTableCellAlignment`。但通用工具栏/宿主工具栏通常会调用 `WenzRichTextController.setAlignment` 或 `ToolbarController` 暴露的块级操作；当前 `SetAlignmentCommand` 只修改顶层 block 的 `BlockAttributes.alignment`，当 selection 位于表格单元格时，修改的是 `TableBlockNode.attributes`，不会影响 cell 内文本渲染，表现为“工具栏设置后无效”。`ToolbarController` 当前也只暴露 `canTableStruct`、`tableCellIsHeader`、`tableCellBackgroundColor`，缺少当前 cell 对齐状态与设置 helper，导致宿主工具栏难以正确分流。

最合理的修复方向是把“当前 selection 的对齐”作为统一语义：普通文本块继续写入 block alignment；表格 cell 选区写入可见 cell 的 `TableCellNode.alignment`，并让 `ToolbarController` 与示例工具栏走同一入口，避免通用工具栏误用块级命令。

## 目标

- 光标或选区位于表格单元格时，点击工具栏居中/左对齐/右对齐/清除对齐能立即修改当前 cell 或多 cell 选区的 `TableCellNode.alignment`。
- 普通段落、标题、引用、列表等非表格文本块继续沿用原有块级 `BlockAttributes.alignment` 行为。
- 表格 cell 对齐不写入 `TableModel.columnAlignments`，也不依赖 `TableBlockNode.attributes.alignment`；清除 cell 对齐后仍按列级对齐或默认 start 对齐回退。
- `ToolbarController` 能向宿主工具栏暴露是否可设置对齐、当前 cell 对齐状态、混合态，并提供统一的设置/清除入口。
- 现有表格浮动工具栏、示例工具栏和公开 controller API 在 table cell 场景下行为一致。
