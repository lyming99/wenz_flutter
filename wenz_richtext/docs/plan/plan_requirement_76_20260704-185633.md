## 背景与影响范围

本需求中的“图片块”按当前项目模型解释为顶层 `ImageBlockNode`，不包含行内图片 `InlineEmbed(embedType: 'image')`。结合现有源码，图片对齐的底层能力已经存在：

- `ImageBlockNode` 继承 `BlockNode`，可复用 `BlockAttributes.alignment` 持久化图片块对齐；rich JSON 已通过 `attrs.alignment` 往返。
- `SetAlignmentCommand` 会更新非表格选择范围内块的 `BlockAttributes.alignment`，`ToolbarController.setAlignment(...)` 在图片 object selection 下可写入图片对齐。
- 默认图片渲染 `_ImageBlockContent` 已使用 `_imageBlockFigureAlignment(block.attributes.alignment)` 移动图片 frame，caption、selection stroke 和 object toolbar anchor 也已跟随 frame。
- 当前主要缺口在图片块自身的对象浮动菜单：`_ObjectMoreMenu` 在 `imageActions=true` 时只提供“图片宽度：小/中/大”和“重置图片尺寸”，`ObjectBlockAction` 也没有图片对齐 action。因此用户选中图片后缺少可发现的图片块对齐设置入口。

本计划聚焦补齐图片对象工具栏的对齐设置能力，不新增 `ImageBlockNode` 字段，不提升 schema version，不改变 `MediaResolver`、图片尺寸 `showWidth/showHeight`、HTML/Markdown/plain text 既有策略。表格单元格对齐、文本块对齐和默认桌面 toolbar 的现有行为保持不变。

## 实施策略

采用最小协议扩展：在 `ObjectBlockAction` 增加图片对齐动作，payload 使用现有 `ObjectBlockActionIntent.value` 承载 `String?` alignment，其中 `'left'`、`'center'`、`'right'` 为有效显式值，`null` 表示清除显式对齐。图片对象菜单在可编辑且 `imageActions=true` 时展示左对齐、居中、右对齐、清除对齐项，并把当前图片 alignment 传入菜单用于 selected/disabled 状态。

执行动作时不通过图片尺寸更新命令扩展字段，而是复用现有 `WenzRichTextController.setAlignment(...)` / `SetAlignmentCommand`，并显式传入目标图片 object selection，保证 selection、permission gate、undo/redo 和跨模块语义与已有 toolbar 对齐链路一致。
