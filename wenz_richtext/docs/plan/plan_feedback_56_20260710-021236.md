# 修复文字颜色选择 popup 的 MouseTracker 断言

## 需求概要

反馈 #56 指出默认富文本工具栏打开或使用文字颜色选择 popup 时触发 Flutter MouseTracker 断言：`!_debugDuringDeviceUpdate` 与 PointerAdded/PointerRemoved 状态不匹配。结合现有代码，文字颜色选择位于 `WenzDefaultDesktopToolbar` 的 `_TextColorMenuButton`，使用 `MenuAnchor`、`MenuItemButton`、`Tooltip` 和色块 `GridView`；点击色块、清除或自定义颜色入口会在菜单关闭和 toolbar 状态更新之间发生同步重建，容易在桌面鼠标指针数据包处理期间移除/重建带 hover 跟踪的菜单节点。计划聚焦桌面默认工具栏文字颜色 popup 的关闭与命令执行时序，保持已有预设色、自定义色、清除、混合状态和禁用状态行为不变，并补充指针/hover 交互回归覆盖。

## 任务拆解

- [x] P001: 修复桌面文字颜色 popup 的关闭与命令执行时序 <!-- scope: lib/src/widgets/default_desktop_toolbar.dart -->
  - 验收要点：点击文字颜色按钮打开 popup、再次点击按钮关闭 popup 时，不再在同一指针事件处理中同步触发导致 MouseTracker 断言的 overlay/MouseRegion 重建。
  - 验收要点：点击预设颜色色块后，菜单能够正常关闭并把选区文字颜色更新为对应 ARGB 值，按钮 tooltip 和图标颜色刷新为新颜色。
  - 验收要点：点击清除文字颜色后，菜单能够正常关闭并仅清除文字颜色，不影响加粗、链接、背景色等其他 inline 属性。
  - 验收要点：快速打开、关闭、重新打开文字颜色 popup，或在色块 hover 状态下点击选择颜色，不抛出 Flutter framework error。
- [x] P002: 保持文字颜色 popup 子项状态与可访问提示一致 <!-- scope: lib/src/widgets/default_desktop_toolbar.dart -->
  - 验收要点：预设色块继续显示选中态 check、hover/pressed 背景和颜色 tooltip，当前颜色为预设色时只对应色块被标记为选中。
  - 验收要点：当前颜色为自定义值时，自定义颜色入口继续显示颜色预览、选中态和 `#AARRGGBB` tooltip，预设色块不被误标记。
  - 验收要点：当前选区为混合文字颜色时，主按钮、清除项、自定义项继续显示混合状态文案，所有预设色块保持未选中。
  - 验收要点：只读或不可格式化状态下，文字颜色 popup 的预设色、清除项和自定义项保持禁用，不执行颜色变更，也不产生指针相关异常。
- [x] P003: 补充桌面文字颜色 popup 指针交互回归覆盖 <!-- scope: test/widgets/default_desktop_toolbar_test.dart -->
  - 验收要点：覆盖鼠标指针进入文字颜色按钮、打开 popup、移动到色块并点击选择颜色的流程，断言 `tester.takeException()` 为空。
  - 验收要点：覆盖文字颜色 popup 打开后直接关闭、再次打开、再选择色块的流程，断言菜单状态、文字颜色状态和异常捕获均符合预期。
  - 验收要点：覆盖清除文字颜色和自定义颜色入口流程，确保修复后的延迟执行或关闭时序不会破坏已有行为。
  - 验收要点：覆盖不可格式化状态下打开文字颜色 popup 的禁用交互，确保 hover、点击禁用项、关闭 popup 均不抛异常。
