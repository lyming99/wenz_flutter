## 背景与现状

项目是 Flutter 富文本编辑器 package，键盘 Enter 的主要路径是 `WenzRichTextEditor._handleKeyEvent` 将按键交给 `EditorShortcutManager.resolve`，随后 `_performShortcut` 调用 `WenzRichTextController.enter(newBlockId: ...)`，最终进入 `EnterCommand`。

当前 `EnterCommand._splitTextBlock` 对所有 `TextBlockNode` 使用同一套分裂逻辑：新块的 `type` 直接继承原块，`_continuedTextBlockAttributes` 也会保留 `level` 等属性。因此当 caret 位于标题块文本末尾时，回车会生成另一个 `BlockType.heading`，而不是用户期望的正文段落。

修复应放在命令层，而不是 UI 键盘层。这样 `controller.enter()`、硬件键盘 Enter、粘贴或后续其它复用 EnterCommand 的入口都能获得一致文档语义。既有代码块内 Enter、表格单元格内 Enter、列表续行、空列表退出、引用块续行/退出等行为不应被扩大修改。

## 目标

- 标题块末尾回车时，在标题后插入一个正文段落，而不是继续插入标题块。
- 新正文段落的 selection 落在新块开头，保持现有 `newBlockId`、历史记录、schema normalize 和回调路径。
- 标题块中部回车、普通段落、列表、引用、代码块、表格单元格等既有 Enter 行为保持兼容。
- 新增测试覆盖命令层和真实 widget 键盘路径，防止只修 controller 或只修 UI 的局部问题。
