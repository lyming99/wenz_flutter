# 开发计划：表格 cell 对齐后的选择高亮修复（反馈 #51）

## 需求概述

反馈指出：表格 cell 设置居中、居右后，文字选择仍存在高亮位置或范围不正确的问题。当前表格 cell 选择高亮仍可能依赖 `TableCellRange.containsCell` 的行列索引矩形，或使用端点整格矩形做近似，导致不在实际可视选择范围内的 cell 被错误高亮。

目标方案：表格多 cell 选择的整格高亮必须以 start 光标和 end 光标的像素坐标为准，计算 `min(left) / min(top) / max(right) / max(bottom)` 得到约束矩形；仅当 cell 的可见矩形与该约束矩形相交时才渲染选中高亮。`TableCellRange` 可继续服务于表格工具栏和结构命令，但不能作为视觉高亮的最终判定依据。

## 现状分析

相关实现集中在 `lib/src/widgets/wenz_rich_text_editor.dart`：

- `_TableBlockRenderer` 通过 `_TableGridMetrics.compute` 生成每个可见 cell 的 `left/top/width/height`，并把 `_shouldHighlightTableCell(...)` 结果传给 `_TableCellSurface.highlightWholeCell`。
- `_selectionRectForTableCells(...)` 已存在，但当前语义是使用 selection start/end 所在 cell 的整格矩形做 union，不是使用 start/end 光标像素坐标。
- `_shouldHighlightTableCell(...)` 在 same-table 多 cell selection 下仍有 `range.containsCell(rowIndex, columnIndex)` fallback，跨块分支也存在行列/row-major fallback，可能再次把不可见范围内的 cell 误判为选中。
- `_TextSelectionSurface` 和 `TextLayoutService` 已经把 `TextAlign.center/right` 交给 `TextPainter` 处理，单 cell 文字级高亮应继续使用 `selectionBoxes` 的真实文字盒，避免用整格高亮覆盖单 cell 局部文字选择。

相关模型在 `lib/src/core/position/document_position.dart`：

- `DocumentSelection.tableCellRange` / `TableCellRange.containsCell` 是纯行列索引矩形，注释也说明不考虑 merged/covered cell 与实际视觉布局。

相关测试集中在 `test/widgets/wenz_rich_text_editor_test.dart`，已有表格拖选、空 cell 命中、居中/居右 cell 选择、merged cell 等覆盖，但缺少“基于光标像素约束矩形排除索引矩形内误选 cell”的回归用例。

## 总体验收标准

1. 表格 cell 多选高亮以 start/end 光标像素坐标形成的视觉矩形为准，不再因 `TableCellRange.containsCell` 的行列索引矩形而误选不可视范围外的 cell。
2. 居中、居右 cell 内的文字级选择高亮位置与实际文本位置一致，选择 offset 不因 padding、垂直居中或 textAlign 偏移而漂移。
3. 单 cell 局部选择、多 cell 整格选择、反向拖选、merged/covered cell、跨块选择的现有行为不发生回归。
4. 最终验收命令范围：`flutter analyze lib/src/widgets/wenz_rich_text_editor.dart lib/src/rendering/text_layout_service.dart test/widgets/wenz_rich_text_editor_test.dart` 与 `flutter test test/widgets/wenz_rich_text_editor_test.dart --name "table"`；通过标准为无新增静态分析问题且测试全部通过。
