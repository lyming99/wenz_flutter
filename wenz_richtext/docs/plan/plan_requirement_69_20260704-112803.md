## 背景与影响范围

本需求涉及 Flutter 富文本编辑器的行级 chrome、todo 复选框、媒体块布局和对象块浮动工具栏。基于当前源码分析，主要影响点如下：

- todo 块按钮由 `lib/src/widgets/wenz_rich_text_editor.dart` 中的 `_TodoCheckbox` 渲染，当前使用 Flutter `Checkbox` 默认交互层，hover 时会出现背景/水波 overlay。
- 左侧块操作按钮由 `_BlockDragHandleOverlay` 与 `_BlockDragHandleButton` 渲染，公共尺寸与 rail 约定在 `lib/src/widgets/block_renderer_registry.dart` 的 `BlockDragHandleSpec`。
- 图片/视频块内容由 `_ImageBlockContent`、`_VideoBlockContent` 与 `_MediaBlockChrome` 渲染，媒体块自身有 `_kMediaBlockMarginVertical / 2` 的上边距，但行级操作按钮当前按普通对象块行顶计算。
- 对象块工具栏由 `_MediaBlockChrome` 发布 `ObjectBlockToolbarOverlayRequest`，最终通过 `lib/src/widgets/object_block_toolbar_overlay.dart` 的 `ObjectBlockToolbarOverlayHost` 显示；当前 overlay 只保存 `visibleTop` 并做顶部 clamp，缺少完整 viewport 可见性判断。
- 现有 widget 回归测试集中在 `test/widgets/wenz_rich_text_editor_test.dart`，已有大纲折叠 rail、媒体对象工具栏滚动跟随、对象工具栏生命周期等相邻测试，适合补充本需求覆盖。

## 实施策略

保持现有编辑器架构和公开 API 稳定，不改文档模型、不改变块命令语义。样式和交互调整优先收敛在 widget 层：todo hover 仅去除背景反馈但保留点击、焦点和可访问性；行级 chrome 继续复用 `BlockDragHandleSpec` 的尺寸约定；媒体块只修正块操作按钮与媒体内容的视觉对齐；对象块工具栏在 anchor 完全离开滚动 viewport 时隐藏，部分可见时仍保持当前跟随定位。

  - 验收要点：`_TodoCheckbox` hover 时不再显示复选框外层背景、hover overlay 或额外填充色，视觉上保持透明。

- [x] P002: 对齐媒体块上边距与块操作按钮垂直位置 <!-- scope: lib/src/widgets/wenz_rich_text_editor.dart -->
  - 验收要点：图片块存在 `_kMediaBlockMarginVertical / 2` 上边距时，左侧块操作按钮的顶部/中心应与图片 frame 的可视顶部区域对齐，不再贴在媒体块外层行顶。
  - 验收要点：同一媒体 chrome 复用路径下的视频块保持一致对齐；代码块、普通段落、列表、todo、分割线等非媒体块的操作按钮垂直位置不回归。
  - 验收要点：选中媒体块时，对象块工具栏、selection stroke、预览按钮与更多菜单的布局不因操作按钮偏移产生跳动。

  - 验收要点：有真实折叠按钮的可折叠标题仍保持“块操作按钮 + chromeGap + 折叠按钮 + gapToContent + 内容”的既有布局，不发生重叠。
  - 验收要点：正文内容左边缘仍保持跨标题、叶子标题、段落、代码块和媒体块对齐；只读模式不显示块操作按钮，可折叠标题的只读折叠按钮仍可用。
