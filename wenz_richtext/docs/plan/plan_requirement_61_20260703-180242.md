# 需求 #61 开发计划：块操作与斜杆 popup Chrome 风格中性色和自适应定位

- 需求编号：#61
- 生成时间：2026-07-03 18:02:42
- 需求内容：块操作以及斜杆 popup，背景色浅灰色/深色，不要用主题色；边框颜色要浅，chrome 风格；斜杆 popup 要自适应显示到上面或者下面，避免尺寸太小。

## 背景与现状

本项目是 Flutter 富文本编辑器组件，块操作入口集中在 `lib/src/widgets/wenz_rich_text_editor.dart` 的块拖拽句柄菜单，斜杆命令弹层由 `lib/src/widgets/slash_menu_overlay.dart` 渲染，并由 `WenzRichTextEditor` 的 `_buildSlashMenuOverlay`、`_slashMenuAnchor` 负责定位。

当前块操作 popup 的 `_popupMenuColor`、`_floatingToolbarSurfaceColor` 使用 `theme.colorScheme.surfaceContainerLow`，边框使用 `theme.colorScheme.outlineVariant.withAlpha(...)`，选中项背景仍使用 `theme.colorScheme.primary.withAlpha(...)`。斜杆 popup 也采用同类主题色派生方式：表面色来自 `surfaceContainerLow`，边框来自 `outlineVariant`，选中项背景和按压反馈来自 `primary`。这与“浅灰色/深色、中性色、不要用主题色、Chrome 风格浅边框”的要求不一致。

斜杆 popup 已有 `opensAbove` 判断，但当前依据主要是下方空间是否小于单个菜单项高度；当下方空间不足但仍大于一项高度时，弹层可能继续向下打开并被压成较小高度。需要改为基于上下可用空间、最小可读高度和键盘遮挡区域的择优定位。

## 实施原则

- 仅调整块操作相关 popup 与斜杆 popup 的视觉 chrome 和斜杆定位逻辑，不改变命令注册、块操作动作、斜杆命令过滤、键盘选择和命令执行语义。
- 颜色使用固定的中性 light/dark token 或等价私有 helper，避免 popup 背景、边框、选中背景继续跟随业务主题主色变化；错误/危险动作文本仍可保留语义化 error 色。
- 斜杆 popup 需要优先选择能容纳合理高度的一侧；上下都不足时选择可用空间更大的一侧，并保持滚动可用、左右不越界、键盘遮挡区域不覆盖。
- 更新现有 widget/golden 断言以覆盖视觉 token 和定位行为；测试命令统一放入最后的完整验收节点。
