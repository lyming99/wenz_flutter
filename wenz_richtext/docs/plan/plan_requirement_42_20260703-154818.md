# 需求 #42 开发计划：拖拽标题大纲时连同子内容移动

- 需求编号：#42
- 生成时间：2026-07-03 15:48:18
- 需求内容：拖拽块时，如果是标题大纲类型时，标题大纲下的子内容要跟着调节位置。

## 背景与影响范围

当前块移动链路分为两层：核心层 `MoveBlockCommand` 只移动单个 top-level block，`WenzRichTextController.moveBlock` 直接包装该命令；编辑器 UI 层的拖拽句柄在 `_submitBlockReorder` 中把 drop target 转成目标索引，再通过 `ObjectBlockActionIntent`、`_moveBlock` 调用 controller。菜单里的上移/下移也复用同一条 `_moveBlock` 路径。

标题大纲的层级范围已由 `WenzOutlineController` 计算：`OutlineItem.collapseRange` 按 `BlockType.heading` 的 H1-H6 level，从标题后一个 block 开始，直到下一个同级或更高级标题前结束。该范围目前用于折叠投影，不改变文档顺序。需求 #42 应复用这套层级规则，但移动范围应包含“标题块本身 + 该标题下所有子内容”，并且在折叠状态下仍移动隐藏的子内容。

本需求不需要改文档 schema、block JSON/Markdown/HTML 编解码语义，也不应改变普通段落、列表、代码、表格、媒体和对象块的单块拖拽行为。

## 实施策略

采用“范围解析 + 连续块移动命令 + UI 统一接入”的方案。核心命令层提供连续 top-level block 范围移动能力，保留现有单块 `moveBlock` 兼容行为；编辑器层在拖拽或菜单移动前判断当前 block 是否为标题大纲类型，若是则解析为标题段落范围，否则退化为长度 1 的普通范围。drop target 落在自身移动范围内时隐藏或 no-op，落在范围外时按原文档插入边界换算成移动后的最终起始索引。

标题范围边界按现有大纲折叠规则解释：H1 覆盖到下一个 H1 前，H2 覆盖到下一个 H1/H2 前，以此类推；低级标题、普通文本、列表、引用、代码、表格、图片、视频、文件、分割线、callout 和业务 block embed 都随父标题一起移动。空标题是否可折叠不影响拖拽分组，只要 block 类型为 heading 且存在有效 level，就按标题层级计算移动范围。
