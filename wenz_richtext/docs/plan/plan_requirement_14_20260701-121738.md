# 需求开发计划：粘贴与拖拽图片输入

## 来源

- 类型：需求
- 编号：14
- 生成时间：2026-07-01 12:17:38
- 原始需求：实现粘贴内存图；粘贴文件图片；粘贴微信/QQ复制的图片；文件拖拽图片到编辑器；

## 需求理解

- 编辑器应支持从系统剪贴板粘贴图片，包括截图/内存位图、复制图片文件、微信/QQ 等 IM 软件复制出的图片数据。
- 编辑器应支持把本地图片文件从系统文件管理器拖拽到编辑器区域后插入为图片块。
- 插入结果应复用现有 `ImageBlockNode` 与 `WenzRichTextController` 命令链路，生成可撤销/重做的图片块，而不是绕过文档模型直接渲染临时 widget。
- 粘贴文本、Wenz rich JSON、HTML/Markdown 等既有剪贴板行为不能回归；图片输入只是剪贴板/拖拽 pipeline 的新增分支。
- 图片的真实上传、业务 asset 映射仍由宿主处理；核心包负责把可识别的图片输入转换成可显示/可保存的 `ImageBlockNode.file` 或宿主可接管的描述。

## 项目分析

- 当前剪贴板链路只支持文本：`WenzRichTextEditor._handlePaste` 只调用 Flutter `Clipboard.getData('text/plain')`，然后走 `WenzRichTextController.pasteText`；`ClipboardService` 是纯逻辑层，只解析 Wenz rich JSON、plain text、HTML、Markdown。
- 当前图片模型与命令已经可复用：`ImageBlockNode` 支持 `file`、`assetId`、尺寸、caption、altText；`WenzRichTextController.insertImage`/`insertBlocks` 和 `PasteBlocksCommand` 已经能把图片块放进历史与 schema pipeline。
- 当前示例已能通过工具栏选择本地图片：`example/lib/main.dart` 使用 `file_selector` 拿到图片路径，再调用 toolbar/controller 插入图片；`example/lib/local_image_view_io.dart` 能用 `Image.file` 渲染 `ImageBlockNode.file`。
- 当前编辑器 drag 只覆盖内部块排序：`wenz_rich_text_editor.dart` 有 block drag handle/drop indicator，但没有接收外部文件拖拽的 drop region。
- Flutter 官方 `Clipboard` 不暴露图片/文件 flavor，外部文件拖拽也不是 core widget 能力；本需求需要新增平台输入适配层。计划引入并封装平台插件能力（调研目标为 `super_clipboard` 读取系统图片剪贴板、`super_drag_and_drop` 接收外部文件拖放），让业务 API 不直接暴露具体插件对象。

## 设计方案

- 新增“外部图片输入”抽象：用统一数据结构表示内存图片 bytes、文件路径、file URI、MIME、文件名、大小等信息，并提供图片类型校验、caption/altText 推导、临时文件写入策略。
- 剪贴板读取分两层：widget/platform adapter 负责读取系统多 flavor 数据，input service 负责把图片数据转成 `ImageBlockNode`/`ClipboardPaste.blocks`；既有 `ClipboardService` 文本解析保持纯 Dart。
- 粘贴优先级：Wenz rich JSON 优先保留原编辑器富文本语义；当剪贴板包含图片 bytes 或图片文件 URI/path 时插入图片块；无图片时继续走 HTML/Markdown/plain text 现有分支。
- 内存图处理：默认 IO 实现把 bytes 写入系统临时目录，生成稳定扩展名（优先根据 MIME：png/jpeg/gif/webp/bmp），再把临时文件路径写入 `ImageBlockNode.file`；Web/不支持平台降级为空结果，不抛异常。
- 文件拖拽：在编辑器 shell 外层增加 drop region，只接受图片文件/图片 bytes；拖入时显示轻量 drop overlay，drop 后按落点或当前 selection 插入图片块；只读态、权限不足、非图片文件不插入。
- 公共配置：在 `WenzEditorConfiguration`/`WenzRichTextEditor` 暴露可关闭开关与可替换的外部图片输入适配/存储接口，宿主可接管上传、缓存路径或安全策略；默认配置保持可运行。
