# 需求开发计划：视频组件选择边框对齐图片组件（全包裹贴框单描边）

## 来源

- 原始需求：视频组件像图片组件那样，要全包裹选择边框

## 项目分析
- 需求中的「全包裹选择边框」指：选中媒体块时只画一条紧贴媒体框（frame）、使用媒体圆角 `_kMediaCornerRadius`(12)、`primary`/`width:2` 的描边，而非铺满整块（含上下 `_kMediaBlockMarginVertical` 边距）的松散矩形。图片组件当前正是这一形态，视频组件出现「双框」偏差。
- 图片选中态渲染路径：`_defaultImageBlockRenderer` → `_withSelectableImageBlock`（`lib/src/widgets/wenz_rich_text_editor.dart:6613`）在其 `_BlockObjectSelectionSurface` 上显式传 `showSelectionOverlay: false`（`:6644`），关闭通用整块覆盖层；实际描边由 `_ImageBlockContent` 内的 `_MediaSelectionStroke`（`:12091`）贴着媒体框绘制，即「全包裹贴框」单条描边。
- 视频选中态渲染路径：`_defaultVideoBlockRenderer` → `_withSelectableVideoBlock`（`:6653`）构造 `_BlockObjectSelectionSurface` 时**未**传 `showSelectionOverlay`，默认为 `true`，于是通用覆盖层（`_BlockObjectSelectionSurface.build`，`:9304-9316`，`BorderRadius.circular(6)`、铺满整块含边距的松散矩形）照常绘制；同时 `_VideoBlockContent` 内也有 `_MediaSelectionStroke`（`:10998`）。两条描边叠加 → 视频选中态出现「松散双框」，正是 `_BlockObjectSelectionSurface.showSelectionOverlay` 文档注释（`:9153-9156`）警告并要求媒体块关闭的情况——视频包装漏传了该开关。
- 安全性确认：`showSelectionOverlay` 仅控制装饰性 `Positioned.fill`（`:9304`），不参与命中测试/几何注册（注册逻辑在 `_register`，`:9199`）；图片组件已长期以 `false` 落地，浮动手柄/双击预览/光标均正常，故对视频同样安全。
- 结论：根因是一行遗漏，最优工程方案是把 `_withSelectableVideoBlock` 对齐 `_withSelectableImageBlock`，给其 `_BlockObjectSelectionSurface` 传 `showSelectionOverlay: false`，使视频选中态只保留 `_MediaSelectionStroke` 这条贴框「全包裹」描边。不改数据模型、codec、命令体系；不动 `_MediaSelectionStroke`/`_MediaBlockChrome`/placeholder/resolver/aspectRatio 逻辑。
