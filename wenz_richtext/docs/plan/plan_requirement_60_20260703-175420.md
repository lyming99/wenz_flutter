# 需求 #60 开发计划：叶子大纲标题折叠按钮与块操作间距调整

## 背景与现状

- 项目是 Flutter 富文本编辑器组件，编辑器主体在 `lib/src/widgets/wenz_rich_text_editor.dart`，块级行操作按钮规格在 `lib/src/widgets/block_renderer_registry.dart`，大纲树面板在 `lib/src/widgets/outline_tree.dart`。
- 当前编辑器 heading 折叠状态由 `_headingCollapseStateFor` 从 `WenzOutlineController.collapseStateForBlockId` 转成 `HeadingCollapseState`；即使 `canCollapse == false`，叶子 heading 仍会渲染禁用的 `_HeadingCollapseButton`。
- 当前块操作与折叠按钮布局通过 `BlockDragHandleSpec.chromeGap` 和 `BlockDragHandleSpec.gapToContent` 控制，现有值均为 `3.0`，不满足需求中的 8dp 间距。
- 当前折叠按钮使用 `_kHeadingCollapseSlotWidth` 包住 `_kHeadingCollapseButtonSize`，实际会给折叠按钮留下额外左侧槽位；当间距提升到 8dp 时，还需要重新推导 rail 宽度，避免块操作按钮与折叠按钮重叠。
- 当前 `WenzOutlineTree` 对不可折叠标题不会渲染 `_CollapseToggle`，但仍用 `SizedBox(width: 24, height: 24)` 保留同等槽位；若需求中的“大纲标题”指侧边大纲树，也应去掉叶子标题的折叠按钮占位。

## 实施原则

- 只改变标题折叠 affordance 与行 chrome 间距，不改变 `WenzOutlineController` 的折叠范围计算、隐藏投影、选择/导航逻辑。
- 有子内容的 heading 继续支持折叠、展开、键盘触发和只读模式触发；没有子内容的 heading 不渲染折叠按钮，也不响应折叠入口。
- 块操作按钮与内容右边距固定为 8dp；块操作按钮与折叠按钮间距固定为 8dp；折叠按钮左侧不再保留额外外边距或空槽。
- 所有 golden 变化仅限于按钮消失和行 chrome 水平位置调整。

## 总体验收标准

- 功能标准：没有子内容的 heading/大纲标题不显示折叠图标按钮，不可点击折叠；有子内容的 heading/大纲标题继续支持折叠与展开。
- 布局标准：块操作按钮到内容的右侧间距为 8dp；块操作按钮到折叠按钮的间距为 8dp；折叠按钮没有额外左外边距，且与内容之间保持 8dp。
- 回归标准：编辑器正文投影、折叠隐藏范围、键盘折叠、只读折叠、块菜单、块拖拽排序、大纲树选择和展开/折叠全部行为不出现回归。
- 最终验收命令：
  - `flutter analyze`
  - `flutter test test/widgets/wenz_rich_text_editor_test.dart test/widgets/outline_tree_test.dart test/widgets/editor_golden_test.dart`
  - `flutter test`
- 通过标准：上述命令全部通过；测试与 golden 断言明确覆盖本需求的可见行为和间距约束。
