# 开发计划：悬浮工具栏滚动位置重新计算修复

## 背景

反馈 #52：悬浮工具栏存在问题，滚动没有重新计算位置。

## 问题分析

编辑器中有两套基于 Overlay 的悬浮工具栏系统，架构高度一致：

1. **表格浮动工具栏** (`lib/src/widgets/table_floating_toolbar_overlay.dart`)
   - `TableFloatingToolbarOverlayAnchor` — 锚点控件，嵌入滚动列表内部，负责追踪表格单元格位置
   - `TableFloatingToolbarOverlayHost` — 宿主控件，位于编辑器根部，通过 `OverlayPortal` 渲染工具栏
   - `_TableFloatingToolbarOverlayEntry` — 浮层条目，通过 `Positioned` 定位工具栏

2. **对象块浮动工具栏** (`lib/src/widgets/object_block_toolbar_overlay.dart`)
   - `ObjectBlockToolbarOverlayAnchor` — 锚点控件，嵌入滚动列表内部
   - `ObjectBlockToolbarOverlayHost` — 宿主控件，位于编辑器根部
   - `_ObjectBlockToolbarOverlayEntry` — 浮层条目，通过 `Positioned` 定位工具栏

### 根因

两套系统的位置重算机制存在相同缺陷：

1. **滚动监听依赖 `didChangeDependencies` 中的 `_syncScrollPosition`** — 该方法在首次调用时通过 `Scrollable.maybeOf(context)?.position` 获取 `ScrollPosition` 并注册 `_scheduleSync` 监听器。但如果此时 `Scrollable` 尚未存在于控件树中，`position` 为 null，与初始 null 值经 `identical` 判等后直接返回，**滚动监听器永远未能注册**。后续 `didChangeDependencies` 仅在 `InheritedWidget` 变更时触发，不一定再次执行。

2. **`build()` 调用 `_scheduleSync()` 是变通而非正确方案** — 每次 build 时注册 post-frame 回调来重算位置。但在纯滚动过程中（ListView 通过 layout 重定位而非 rebuild），锚点控件不 rebuild，因此 `_scheduleSync` 不会被调用，工具栏位置保持冻结。

3. **缺少 `NotificationListener<ScrollNotification>`** — 浮层宿主和条目层均未监听滚动通知，无法感知滚动发生并触发位置更新。

4. **`_scheduleSync` 内置去重守卫 `_syncScheduled`** — 在快速连续滚动事件中，仅第一个事件注册回调，但回调执行时使用锚点的最终位置，理论上可接受。然而若滚动监听器根本未注册，此守卫无意义。

### 影响范围

- `lib/src/widgets/table_floating_toolbar_overlay.dart` — 表格浮动工具栏完整实现
- `lib/src/widgets/object_block_toolbar_overlay.dart` — 对象块浮动工具栏完整实现
- `test/widgets/wenz_rich_text_editor_test.dart` — 已有表格工具栏滚动测试，但覆盖不足

---

## 总体方案

对两套悬浮工具栏系统做统一修复：

1. **移除 `build()` 中的 `_scheduleSync()` 调用** — 不再依赖重 build 驱动位置同步，改为纯滚动驱动。
2. **通过 `NotificationListener<ScrollNotification>` 在锚点层监听滚动** — 替代当前脆弱的 `ScrollPosition.addListener` 方式，确保每次滚动都触发位置重算。
3. **优化 `_scheduleSync` 去重逻辑** — 确保快速滚动时不丢帧也不重复计算。
4. **补充全覆盖测试** — 验证滚动过程中表格工具栏和对象块工具栏位置正确跟随。

- [x] P001: 修复 TableFloatingToolbarOverlayAnchor 滚动位置重算 <!-- scope: lib/src/widgets/table_floating_toolbar_overlay.dart -->
  - 验收要点：
    - 移除 `build()` 方法中的 `_scheduleSync()` 调用

    - 确保 `ScrollNotification` 的 `metrics` 可用于判断是否需要重算（避免 extents 变化误触发）

    - `didChangeMetrics` 中保留 `_scheduleSync()` 用于窗口尺寸变化
