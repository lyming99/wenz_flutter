# 反馈 #59 开发计划：大纲折叠按钮与操作按钮增加间距

- 反馈编号：#59
- 生成时间：2026-07-04 10:11:04
- 反馈内容：大纲折叠按钮和操作按钮要有间距，目前挤到一块了

## 背景与现状

项目是 Flutter 富文本编辑器 package。反馈对应编辑器正文标题行左侧的 row chrome：块操作/拖拽按钮由 `lib/src/widgets/wenz_rich_text_editor.dart` 中的 `_BlockDragHandleButton` 渲染，标题大纲折叠按钮由同文件的 `_HeadingCollapseButton` 渲染，二者在 `_BlockDragHandleOverlay` 的 `Stack` 中通过 `PositionedDirectional` 定位。

当前 `_BlockDragHandleOverlay` 在可编辑模式下把 `activeChromeWidth` 计算为 `BlockDragHandleSpec.hitSize.width + BlockDragHandleSpec.gapToContent`，随后用 `activeChromeWidth - _kHeadingCollapseButtonSize` 作为折叠按钮起点。以现有常量计算，操作按钮占 28 dp，折叠按钮占 24 dp，折叠按钮起点为 12 dp，实际会覆盖操作按钮的 12-28 dp 区间，表现为两个按钮挤在一起甚至重叠。`BlockDragHandleSpec` 已定义 `chromeGap = 8.0` 用于相邻 row chrome hit target 间距，但当前定位没有使用该间距。

修复方向是让 `_BlockDragHandleOverlay` 使用明确的 row chrome 布局：操作按钮、chrome 间距、折叠按钮、内容间距依次排列；同时保持标题、正文和只读模式的对齐语义，不改变折叠状态模型、拖拽排序、菜单打开和 selection exclusion 机制。

## 目标

- 可编辑模式下，标题行的大纲折叠按钮与块操作/拖拽按钮之间存在稳定间距，不再重叠或贴边。
- 折叠按钮、操作按钮各自保持完整 hit target、tooltip、键盘触发和 selection exclusion 行为。
- 挂载 `WenzOutlineController` 时，标题行与非标题行正文起始位置仍保持一致，不因某些行显示折叠按钮而出现文本左右跳动。
- 只读模式继续显示可用/禁用的大纲折叠按钮，且不引入不存在的操作按钮占位。
- 现有大纲折叠、块操作菜单、块拖拽排序、叶子标题禁用态、golden 视觉基线和相关 widget 测试同步更新。
